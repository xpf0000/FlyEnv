# AI Memory 用户界面交付改进验收

日期：2026-11-05。用户要求：以可上线交付用户使用为目标循环处理，界面沿用 FlyEnv 风格。本轮在当前工作区完成，未提交、未推送、未发布。

## 交付内容

- 使用宿主 `soft-index-panel main-right-panel`、分段标签和 Element Plus 主题。记忆管理、Agent 接入、维护独立呈现；补齐折叠侧栏图标。
- 项目与关键词作为主要入口，高级筛选按需展开。项目选择同时展示路径以区分同名目录。表格浏览、详情抽屉、前后翻页、空/加载/失败状态；混合检索保留全局归属标识。
- 手工新建主要填写标题、摘要和正文；其他字段折叠。默认来源明确为用户手工录入，不伪造 Agent 来源。弹窗内必填校验、错误说明、原请求确认和冲突后读取最新版本。技术 ID/版本等保留在折叠详情。
- 接入分为服务与工具、客户端连接、手工规则、真实调用验证四步。仅展示非敏感服务状态和工具数量；配置/复制结果与真实客户端验证明确分开。
- 维护提供人类可读的调用表格、数据目录、折叠备份说明和映射检查；保留无法检查及恢复缺项，不将失败显示为零问题。
- 所有异步操作沿用 MemoryController 单例；无新增 Pinia、config.setup 持久化、业务外泄或服务生命周期例外。

## 独立审查闭环

独立 reviewer 只读审查后提出五项 Important，全部处理，没有延后问题：

1. 操作回执混入其他记录/归档弹窗：controller 按 request_id 提供操作，弹窗只绑定自己的提交；全局恢复入口保留在管理页。新增归属回归先 RED 后 GREEN，真实界面验证 A 删除失败后 B 不显示 A 的重试。
2. 时间选择产生本地时区偏移、协议只接受 UTC：编辑器统一转 ISO UTC，再复用现有校验；时区转换及协议测试 RED→GREEN。
3. 映射检查遗漏目录读取失败和 previous 恢复缺项：展示警告，目录读取失败时数量显示未知，并列出旧映射恢复后会失去关联的项目。恢复展示模型回归 RED→GREEN。
4. 混合结果丢失范围标识：恢复全局条目标识及详情归属，保留原先正确的 scope/ID 路由。
5. 敏感 IPC 监听超时清理后迟到响应可能记录 token：敏感标记改为请求身份的一部分，监听释放及重复终态后仍脱敏，不依赖无限保留的 key 集合。真实 IPC 模块注入迟到进度/终态/重复终态的回归 RED→GREEN。
