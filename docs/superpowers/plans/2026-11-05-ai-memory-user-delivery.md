# AI Memory 用户交付改进

依据：已批准的 AI Memory design/V1 与实施计划；本轮用户要求以可上线交付为目标循环处理，UI 对齐 FlyEnv。

## 设计与范围

采用现有 FlyEnv `soft-index-panel main-right-panel`、分段标签、Element Plus 表格/抽屉/表单和主题变量。记忆管理、Agent 接入、维护分别呈现；主界面只保留项目、关键词和常用操作，高级筛选与技术信息按需展开。保留现有文件协议及可靠性语义。

取舍：单纯美化旧页面不能解决首次使用和错误恢复；新增独立引导产品会重复 MCP 管理。采用插件内清晰分区、复用现有 MCP 设置，手工规则接入提供明确说明和验证提示。自动安装规则、历史回滚和路径重绑定仍依原方案后置，不伪称已实现。

当前工作区继续修复；保留本会话侧边栏修复。无新增 Pinia、config.setup 或生命周期例外，不修改用户正式库，不发布或推送。

## 操作合同与失败边界

- view：分区、筛选、选中项、对话框、草稿属于挂载页面；领域与异步状态属于现有 MemoryController 单例，持久偏好继续 Storage。
- 连接检查：controller 拥有，跨页面；读取 MCP 配置/状态，仅暴露服务状态与记忆工具开关，不向页面暴露 token；重复调用复用 flight；终态成功或可恢复失败，IPC 监听/超时均清理。它不启动服务，不静默启用工具；失败不影响已保存记忆。
- 保存/修改/归档/删除：复用现有 controller，固定 request_id、revision 与输入；code 200 非终态；未知结果保留原请求、明确确认，不能重建；弹窗内可看见错误/恢复按钮，离页操作仍完成。
- 目录选择/复制验证提示：由 controller action 管理 IPC/通知及异常，页面只接收选择值。取消为取消，不报告失败。复制不等于 Agent 调用通过。
- 列表、详情与项目登记仍由同一 worker 管理；错误提示不吞文件失败。诊断/连接检查属于独立操作，不覆盖记忆读写结果；仅投影白名单元信息。

2. FlyEnv 风格管理页：分段导航、项目/搜索工具栏、表格和详情抽屉、空/加载/错误状态、高级筛选；可回到上一页，切换条件清理旧详情和分页。
3. 简化编辑：标题/摘要/正文为主要输入，其余展开；来源有真实的手工输入默认值；必填/字节/来源校验在弹窗内；unknown/conflict/partial 有可操作恢复。
4. Agent 接入按服务与工具、客户端连接、规则、实际验证分步骤；维护用人类可读状态/表格替代 JSON，保留必要离线恢复步骤于折叠说明。
