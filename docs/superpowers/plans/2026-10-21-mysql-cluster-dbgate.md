# MySQL Cluster details and DbGate

User requests password-form padding, visible source/replica roles, click-to-copy Socket with yellow hover, and a DbGate button beside the instance title whenever any instance runs. Implementation stays plugin-only with no shared config/Pinia/host types/prototype changes.

## Operation contract

- Static GTID roles come from the existing saved member order, independent from credentials, SQL health and process startup. SQL observation remains explicit and supplementary. GR primary/secondary still requires actual group status, not a topology guess.
- Socket copy stays in InstanceActionController: immutable address, duplicate requests share the promise, success notice follows clipboard completion, failure is local and retryable. UI binds the command; no view-owned IPC.
- DbGate renderer opening belongs to a plugin-local singleton controller, survives view changes and shares duplicate calls. Admission requires a running plugin instance and selected NodeJS; capture the selected Node descriptor before sending. Raw code=200 install notices remain nonterminal; code=0/1, timeout or synchronous errors close notices/listeners and release busy. Use sensitive IPC because terminal URL contains web-panel credentials. Browser-open failure reports its own failure without replaying a started panel.
- Fork owns DbGate process/files through the existing DbGateRuntime with private mysql-cluster paths. Adapt native runtime metadata to plugin identity and provide companion stop args so main's existing exit cleanup retains the correct process. Panel opening and parent stop admission are serialized for the shared companion; last-parent stop first confirms DbGate stop, then stops that MySQL instance. A required companion failure must not claim the parent stopped. Independent MySQL instances remain stopped through existing runtime/ModuleInstalledItem methods; one remaining or unknown parent does not authorize companion shutdown. Concurrent open/stop/hide must not orphan a late panel, and plugin cleanup must never stop MongoDB's separate panel.

## Verification

Regressions: GTID roles without credentials and after failed SQL observation; copy snapshot/duplicate/failure; DbGate missing Node/running instance, immutable request/clone boundary, duplicate and code200 retention, terminal/error/timeout cleanup, browser failure; isolated Fork runtime/adapters for companion identity, last-parent ordering, failed cleanup, parallel stops and open-stop handoff. Full plugin suite, lint/type baseline, existing operation boundary audit and packaged Fork entry. Isolated UI preview confirms padding/header visibility/Socket actions. No real DbGate npm installation or user processes are needed for regression verification.

Review refinements: companion decisions require a fresh process observation because a frozen batch stop table still contains already-stopped siblings. This observation is confined to companion lifetime; actual MySQL termination retains the existing candidate/stop contract. Never-installed private panels skip companion discovery entirely. An unknown parent is not proof of final-parent shutdown, and retained private PID files block the dependent parent stop. A native isolated Node HTTP fixture additionally exercises the actual shared runtime/start/identity/health/stop path without installing DbGate or touching user databases.
