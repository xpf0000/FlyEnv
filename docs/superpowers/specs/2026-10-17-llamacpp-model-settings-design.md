# llama.cpp 模型关联与高级设置优化方案

日期：2026-10-17
关联需求：[#905 — Add mmproj support and advanced model settings](https://github.com/xpf0000/FlyEnv/issues/905)
状态：用户已于 2026-10-17 批准设计并要求编写实施计划；[实施计划](../plans/2026-10-17-llamacpp-model-settings.md) 已另行记录，产品代码尚未开始修改。

## 1. 要解决的问题与交付目标

用户已通过 FlyEnv 下载主模型与 mmproj，但启动命令没有加载投影文件，导致文字请求正常、图片请求失败。用户希望通过图形界面管理本地模型，接入 Cline 等客户端，并保留每个模型的启动设置。

本方案覆盖六项结果：

1. 为一个主模型明确关联一个 mmproj，启动时可靠地转换成 `--mmproj`。
2. 主模型、投影文件、草稿模型具有不同角色，列表与选择器不再笼统地把所有 GGUF 当作可启动模型。
3. 服务设置与每模型设置分开保存；切换模型恢复该模型的设置。
4. 常用高级设置使用表单，其余参数通过额外启动参数补充。
5. 用户能在启动前看到命令，在启动后区分实际运行配置与下次启动配置。
6. 不支持、配置冲突、文件失效和部分完成均有明确处理规则。

设计假设：沿用当前单个 llama-server、一次加载一个主模型的模式；本次不建设多模型 Router，不增加聊天、图片上传或音频录制界面，不改宿主公共服务体系。

## 2. 当前实现与上游依据

### 2.1 仓库现状

- `plugins/llamacpp/shared/types.ts`：`LaunchProfile` 仅有基础资源、网络和认证字段。
- `plugins/llamacpp/fork/config.ts`：`buildServerInvocation()` 仅生成基础启动参数；已有 `--help` 检查，但检查方式不能直接承担完整高级参数解析。
- `plugins/llamacpp/render/controller.ts`：以 Storage 保存一份公共 profile 与选中模型，已有模型下载、切换和回退控制器。
- `plugins/llamacpp/shared/modelFile.ts`、`fork/gguf.ts`：已有主模型排除规则和 GGUF 轻量检查，mmproj 不应因此被改成可独立启动的模型。
- `render/Index.vue`：保留“服务 / 版本管理 / 模型 / 设置 / 日志”五个页签。
- `render/models/Index.vue`：模型库已经能下载辅助 GGUF；主要缺少文件角色细分、关联关系和配置入口。
- `render/aside.vue` → `startExtParam` → fork `_startServer()` → `serviceStartSpawn()`：已有通用生命周期，继续复用。

### 2.2 上游证据与可信边界

核对了 issue 所用的 **b10549** 文档，而不是仅依据不断变化的 master。该版本文档包含 mmproj、多模态、Flash Attention、KV cache、思考模式、模板和投机解码相关入口。实际安装二进制仍须按自身能力检测，不能仅凭 build 编号开放选项。

- [b10549 多模态说明](https://github.com/ggml-org/llama.cpp/blob/b10549/docs/multimodal.md)：本地文件模式需要主模型与投影文件分别传参；`-hf` 自动下载投影文件的行为不等于 FlyEnv 当前的本地 `--model` 启动模式。
- [mmproj 工作原理](https://github.com/ggml-org/llama.cpp/blob/b10549/tools/mtmd/README.md)：投影组件与主语言模型分离，匹配关系不能只靠文件扩展名判断。
- [b10549 Server 参数](https://github.com/ggml-org/llama.cpp/blob/b10549/tools/server/README.md)：本文参数映射的参考；具体参数名、别名、枚举及默认值最终以安装版本的 `--help` 为准。
- [b10549 投机解码说明](https://github.com/ggml-org/llama.cpp/blob/b10549/docs/speculative.md)：普通 draft、专用 draft 和主模型内 MTP 头是不同路径，不能共用一个“加速开关”来掩盖依赖。

证据分三级：文件元数据可提供候选与疑似能力；运行时 help 可确认参数语法支持；实际加载与 API 返回才能证明当前组合的运行能力。未实机验证 issue 中的模型、投影文件及 CUDA 组合，不将“参数存在”写成“模型已兼容”。

## 3. 方案选择

| 方案 | 收益 | 局限 | 结论 |
| --- | --- | --- | --- |
| 每模型表单 + 明确文件关联 + 额外参数 | 常见需求易用，文件依赖可追踪，仍保留扩展能力 | 要维护参数描述和兼容规则 | 推荐 |
| 仅增加额外参数文本框 | 修改少，熟悉命令的用户可以立即使用 | 文件关系不可见，容易重复参数，普通用户仍要自行写命令 | 可作为中间交付，不能作为完整方案 |
| 扫描同目录后自动绑定所有附件 | 初次操作少 | 同仓库有多套投影/草稿时容易误配，无法证明兼容 | 不采用静默绑定 |

最终采用：**推荐候选，用户明确选择；常用项表单化，额外项可扩展；保存与应用分离。**

## 4. 配置归属、标识与持久化

### 4.1 服务公共设置

所有模型共用：监听地址、端口、现有 API key 文件，以及后续确有必要的服务级网络配置。版本/后端选择继续由现有版本管理负责，不在模型配置里保存另一份“当前运行时”。

本次不顺带扩大 Windows 认证支持或改现有网络限制；原有服务设置的限制继续生效。

### 4.2 每模型设置

属于指定主模型：投影关联、上下文、CPU 线程、推理资源、高级推理设置、模板/思考、投机解码、采样默认值、额外启动参数和可选 API 模型别名。

模型设置内增加少量 **backendOverrides**，仅覆盖设备名称、GPU 层数、多 GPU 分配、投影 offload/设备及 draft GPU 设置。CUDA 的 `CUDA0` 不自动带到 Metal/Vulkan。通用项不因切后端被复制成多套 profile。

CPU 后端的有效 GPU 层数为 0、设备为空；保留此前 GPU 后端的独立设置，不删除它，也不将 CUDA 的显式配置伪装成 CPU 配置。

### 4.3 文件身份与替换

- 主模型配置键复用现有 `modelFileKey(repoId, revision, path)`，避免把本地绝对路径作为唯一身份。
- 同时保存可用的文件指纹：下载时已有的 SHA-256、大小及已知来源。内容发生变化时要求确认沿用配置，不能只因名称相同就认定原关联仍有效。
- `revision: main` 只表示来源分支，不当作不可变 commit。已有历史下载不补造 resolved commit；新记录若能取得真实 commit 则记录，不能用当前 main 冒充下载时版本。
- 重新下载相同文件且指纹一致时，可以继续使用原配置；路径重定位通过文件记录解析，不自动遍历磁盘寻找“同名替代品”。
- 删除主模型时删除该模型的配置，关联附件仍保留；删除附件见第 5.6 节。

### 4.4 建议数据结构

不要求照搬以下命名，但实现必须保留这些边界：

| 对象 | 内容 |
| --- | --- |
| `LlamaCppSettingsV2` | schemaVersion、service、selectedModelKey、modelProfiles、迁移后的初始模型默认值 |
| `ModelProfile` | modelKey、fingerprint、profileRevision、基础参数、multimodal、performance、chat、speculation、sampling、extraArgsText、backendOverrides |
| `ModelFileRef` | managed 文件的 fileKey，或 external 文件的绝对路径；附可用指纹和角色信息 |
| `PreparedLaunch` | 解析后的文件路径、bin、argv、cwd、配置 revision、运行时身份、校验结果、来源摘要 |
| `ActiveLaunchSnapshot` | 本次实际启动采用的配置与命令，区别于后来保存的新配置 |

模块数据只使用 `StorageGetAsync` / `StorageSetAsync`；不新增 Pinia，不写入 `config.setup`。无例外授权需求，修改保持在 `plugins/llamacpp/` 内。

### 4.5 旧数据迁移

1. 首次读取旧 schema 时，拆出公共网络/认证设置。
2. 将旧基础 profile 复制给旧选中的主模型；其他已下载主模型采用这组基础值作为初始值，以保持原来切换模型沿用资源设置的体验。
3. 新高级字段均为“跟随运行时默认”，多模态为“未关联”，不扫描后直接启用。
4. 新模型采用迁移后固定的初始基础值，不能偷偷复制最近编辑模型的 mmproj、模板、额外参数或设备设置。
5. 完整写入 V2 成功后才在内存采用新配置；失败保留旧配置、原键及迁移输入，允许下次重试。迁移幂等，不产生重复模型配置。
6. 一次保存写入一个 V2 配置快照；不把一次模型设置保存拆成多个互相依赖的 Storage 写入。保留旧键供问题回溯，不在首轮迁移中清理。

## 5. mmproj 关联规则

### 5.1 一个主模型关联一个投影文件

在“模型设置 → 多模态”里提供：

- **投影模式**：`未配置` / `仅文本` / `使用投影文件`，默认未配置；本地模型在未配置时按仅文本启动。这样可以区分“尚未选择”与“用户明确禁用投影”，额外参数不能覆盖后者。
- **mmproj 文件**：已下载投影文件选择器，可搜索；另有“选择本地文件”按钮。
- **投影 GPU 卸载**：跟随运行时 / 开启 / 关闭。
- **投影设备**：默认 / 所选运行时可用设备；仅在该版本支持时显示。
- **图片 token 范围**：高级展开，见参数范围。

一个主模型至多有一个有效 `--mmproj`。多个主模型可以共享同一个投影文件，例如同一基础模型的 Q4、Q5、Q8 量化版本；不要求投影量化名必须与主模型相同，BF16 投影也不因主模型 Q4 而被排除。

音频、图片、视频的能力用标签说明，不能设计成互相独立的“开启图片/开启音频”开关。加载投影并不能让任意语言模型获得任意模态。首版文件关联面向运行时接受的单个 projector；特殊模型的额外组件没有被可靠支持时，明确显示未支持该组合。

### 5.2 候选从哪里来

文件角色扩展为：`主模型 / 多模态投影 / 草稿或 MTP 辅助文件 / GGUF 分片 / 其他辅助文件 / 未识别`。

优先根据有限 GGUF 元数据、张量特征及已知规则分类，名称只做辅助。现有 `standalone=false` 只能证明不能独立启动，不能直接证明它就是 mmproj。解析需有长度与时间上限，不加载模型权重；损坏文件单独标记原因，不中断整个模型列表。

候选顺序：

1. 同一 repo、相同已解析 commit，且角色为 projector。
2. 同一 repo、相同记录 revision，且角色为 projector；只有分支名时标注“同来源，版本未确认”。
3. 其他已下载 projector，显示来源和文件名，由用户自行选择。
4. 通过本地选择器引用外部 projector，显示“本地文件，来源未知”。

同级候选按目录接近程度、可用架构线索排序；不靠文件名相似度宣称匹配。**只有一个候选也只推荐，不静默保存关联。**多个候选不擅自选择最新、最大或 BF16。

### 5.3 本地文件引用

系统选择器筛选 `.gguf`，选择后由 fork 检查绝对路径、文件可读、GGUF 格式与可识别投影信息；只引用原文件，不复制大文件。保存记录其真实路径及可用指纹；不为此新增任意主模型路径导入。

外部文件不进入 FlyEnv 的“删除磁盘文件”所有权范围，用户只能解除引用或定位文件。来源未知或元数据无法证明兼容时提示“尚未验证匹配”；明确是主模型、分片或格式损坏时拒绝作为 projector。未知 projector 变体允许专家确认使用，最终由运行时加载验证，不通过主模型检查器误拒所有投影。

### 5.4 下载后的关联体验

- 下载主模型成功后，若发现同来源候选，显示一条非阻塞提示：“检测到可用投影文件，配置后可尝试多模态输入”，提供“配置”入口。
- 下载 mmproj 成功后，显示“关联到模型”入口；用户选择目标模型并保存。
- 同来源投影尚未下载时，模型设置里提供“查看同仓库文件”，打开现有模型库对应仓库，不自动下载所有辅助文件。
- 下载完成与关联完成分别报告。下载成功后关联保存失败，提示“文件已下载，关联未保存”，只重试保存，不重新下载。
- 推荐计算和通知都是附加动作，其失败不能推翻已完成下载。

### 5.5 启动前与启动后

启动前解析投影真实路径，复查文件可读、身份和参数支持；选择了投影但文件缺失时阻止启动，不能悄悄退回仅文本。用户主动改为仅文本后才省略投影参数。

启动成功以后，尽力读取当前版本支持的模型/属性 API，展示实际报告的多模态能力。若 API 不提供能力或需要当前认证而不可读取，显示“投影已配置，能力未确认”；不把 API 观测失败升级成启动失败。

当前运行信息区分：“未传入投影”“已配置，待重启”“本次已传入投影，能力待确认”“运行时报告支持图片/音频”等状态。配置启用后，若运行时明确报告缺少预期能力，提示查看加载日志；不能显示“已支持图片”仅因 argv 中有 mmproj。

### 5.6 解除关联与删除

- 解除关联只改配置，不删除文件。
- 删除被引用的托管附件前列出所有引用模型，默认要求先解除引用；不能按一个通用删除按钮直接破坏多个模型配置。
- 运行中模型实际使用的主模型、投影、模板文件、draft 文件禁止由插件删除，即使其下次配置已解除引用，也要根据运行快照判断。
- 服务停止后可解除关联并删除；若另一个进程占用文件，正常报告删除失败。
- 用户在 FlyEnv 外移动/删除文件，保留失效关联与原路径，提供“重新选择”和“改为仅文本”；不自动替换文件。

## 6. 高级设置的具体范围

### 6.1 通用交互规则

新高级项默认均为“跟随运行时默认”，未显式设置就不输出对应参数；不要把某个上游版本的默认值永久写进用户配置。布尔项使用 `默认 / 开 / 关`，枚举项提供 `默认`，数字项允许清空并标注单位。

既有上下文、线程、GPU 层数迁移时保留实际数值，避免升级后资源占用突变。新增数字项的特殊值如 `0`、`-1` 必须按该参数含义处理，不能用 `value || default` 吞掉。

每项展示中文名称、必要的简短说明；CLI 名称放在提示或参数详情中。明确的运行时不支持禁用控件并说明原因；已保存的值仍可查看、清除，不能因换版本而丢失。

### 6.2 基础参数与资源

| 设置 | 建议控件 / 默认 | 映射与约束 |
| --- | --- | --- |
| 上下文长度 | 数字，保留旧值；新建可选默认 | `--ctx-size`；支持 `0` 的版本可显示“按模型默认”；不宣称输入值一定等于每个并发槽的实际上下文 |
| 生成线程 | 数字，保留旧值 | `--threads` |
| 提示处理线程 | 默认 / 数字 | `--threads-batch` |
| GPU 层数 | 默认 / 全部 / 数字 | `--n-gpu-layers`；auto/all 仅在实际参数支持时开放，旧版使用其原有数值语义 |
| GPU 设备 | 默认 / 多选 | `--device`；来自对应运行时设备列表，保留现有手输能力 |
| 批处理大小 | 默认 / 数字 | `--batch-size` |
| 微批处理大小 | 默认 / 数字 | `--ubatch-size`；显式值不得大于 batch-size |
| 并发请求槽 | 默认 / 数字 | `--parallel`；提示会改变内存与上下文分配，实际值以运行时为准 |
| API 模型别名 | 文本，可空 | `--alias`；用于客户端选择模型，不改变文件身份 |

### 6.3 性能与内存

| 设置 | 控件 | 映射与注意事项 |
| --- | --- | --- |
| Flash Attention | 默认 / auto / on / off | `--flash-attn`；不同版本值形式不同，按能力映射 |
| K cache 类型 | 默认 / 支持类型下拉 | `--cache-type-k` |
| V cache 类型 | 默认 / 支持类型下拉 | `--cache-type-v`；与 K 分开，量化可能影响精度和后端兼容 |
| KV cache GPU 卸载 | 默认 / 开 / 关 | `--kv-offload` / `--no-kv-offload`，或当前版本实际别名 |
| 模型加载方式 | 默认 / 该版本支持方式 | 新版 `--load-mode`；老版只显示可准确映射的 mmap/mlock 选项，不用新值硬套老版 |
| 连续批处理 | 默认 / 开 / 关 | `--cont-batching` / `--no-cont-batching` |
| 上下文移位 | 默认 / 开 / 关 | `--context-shift` / `--no-context-shift`；不能用它承诺突破模型能力 |
| 多 GPU 分配 | “更多资源设置”内展开 | split mode、tensor split、main GPU；只展示所选运行时支持项，并检查设备数与比例 |

KV 类型不能只硬编码一套永久下拉。常见选项可包括 f32、f16、bf16、q8_0、q4_0、q4_1、iq4_nl、q5_0、q5_1，但每个构建实际可选项必须从能力结果取得，不保证全部后端可运行全部类型。解析 help 中明确列出的允许值，结合模块内已知描述展示；无法得知枚举时保留“默认”和已知可验证项，其他通过额外参数输入并标为需运行时验证。

不在第一轮加入 NUMA、线程亲和性、tensor override、MoE 专门策略、RoPE/YaRN、LoRA 管理等表单。这些低频且依赖更多上下文的参数保留在额外参数入口；避免把所有上游开关搬进设置页。

### 6.4 多模态

| 设置 | 控件 | 映射与约束 |
| --- | --- | --- |
| 投影模式与文件 | 模式选择 + 文件下拉/本地选择 | `--mmproj`；仅文本时不传投影，不假装本地模式会自动找文件 |
| 投影 GPU 卸载 | 默认 / 开 / 关 | `--mmproj-offload` / `--no-mmproj-offload` |
| 投影设备 | 默认 / 单设备 | `--mmproj-device`，仅支持版本出现 |
| 每图最少 token | 默认 / 非负整数 | `--image-min-tokens`；只对适用的动态分辨率模型有效 |
| 每图最多 token | 默认 / 正整数 | `--image-max-tokens`；两者显式设置时 min 不得大于 max |
| 多模态编码批次 token 上限 | 默认 / 正整数 | `--mtmd-batch-max-tokens`；置于“更多多模态设置” |

音频/视频不提供伪造的通用开关；只展示模型与运行时报告的能力、入口要求及当前未知状态。特殊音频生成、声码器、视频处理参数需要单独验证模型路径后再补专用表单，本次不保证所有模态端到端可用。

### 6.5 思考模式、聊天模板与工具调用

| 设置 | 控件 | 行为 |
| --- | --- | --- |
| 思考模式 | 默认 / auto / on / off | 优先当前版本 `--reasoning`；不等价于移除输出中的 think 标签 |
| 思考预算 | 默认 / 不限 / 关闭 / token 数 | 当前版本支持时映射 `--reasoning-budget`，保留 0 与 -1 的明确语义 |
| 思考强度 | 默认 / 当前版本支持等级 | `--reasoning-effort`；模板可能不消费该值，不能显示为模型保证支持 |
| 思考输出格式 | 默认 / 支持格式 | `--reasoning-format`；说明这是输出解析格式，区别于是否产生思考 |
| Jinja 模板处理 | 默认 / 开 / 关 | `--jinja` / `--no-jinja` |
| 聊天模板来源 | 模型内置 / 内置模板名 / 本地模板文件 | 后两种分别映射 `--chat-template`、`--chat-template-file`；三选一 |
| 模板附加参数 | 可折叠 JSON 对象编辑区 | `--chat-template-kwargs`；本地先检查 JSON 对象类型，作为单个 argv 值传入 |

思考设置、模板附加参数中的同义键可能互相覆盖。例如表单关闭思考，同时 kwargs 启用对应模板的 thinking 字段，应标出冲突位置；模块已知的模板可以识别常用键，未知模板保留“无法确认语义”的提示，不自造全模板兼容转换。

旧运行时缺少统一 reasoning 参数时，不静默改成某个模板 kwargs；只有已验证的“模板 + 参数”映射才提供明确兼容选项。

本次不提供“开启 Cline 工具调用”开关。工具调用受客户端请求、模型训练、模板及运行时解析共同影响；可显示运行时报告的模板能力，并提供模板配置入口，不能默认强制所有模型改为 chatml。

### 6.6 投机解码与 MTP

采用“默认/关闭/单一策略”选择器，不把所有策略堆成一组开关。首版结构化支持普通 draft、主模型内 MTP 和一个基础 ngram 策略；运行时实际不支持的选项不可选。其他组合通过额外参数使用并保留高级说明。

| 策略 / 设置 | 所需内容 | 处理规则 |
| --- | --- | --- |
| 默认 | 无 | 不输出投机参数 |
| 关闭 | 无 | 当前版本支持时显式 none |
| 普通草稿模型 | 明确选择 draft GGUF | 使用该版本的 draft model 参数及普通 draft 策略；可选草稿 token 上限、线程、GPU 层数/设备 |
| 主模型 MTP | 主模型包含可用 MTP 头，且运行时支持 | 使用对应 MTP 策略；不要求用户把 mmproj 当作 MTP 文件，也不因名称带 MTP 就宣称可用 |
| 基础 ngram | 无额外模型文件 | 映射一个已核实策略及其基础长度设置；不承诺所有负载都提速 |
| EAGLE / DFlash / DSpark 等 | 模型专用附件与依赖 | 本次不提供未经验证的一键表单；通过额外参数使用，后续按独立组合扩展 |

独立 MTP 文件并非所有版本都按同一种方式加载；若目标组合需要额外 MTP 权重，必须先确认该版本的真实载入接口，再增加专用模式，不自动将其塞入普通 draft 字段。

草稿文件与投影文件分别引用，不能共用一个“辅助模型”输入。draft 可引用另一个已下载主模型或选择外部文件，但不能仅因它可以独立启动就推断其 tokenizer/架构与目标兼容；明确不匹配时阻止，信息不足时提示待加载验证。草稿不作为另一个常驻服务启动，不新建 companion 生命周期。

### 6.7 采样默认值

放在默认折叠的“采样默认值”组：temperature、top-p、top-k、min-p、repeat penalty、presence penalty、frequency penalty、seed，以及默认最大输出 token。都可留空，分别映射当前版本支持的采样/预测参数。

这是服务默认行为，Cline 等客户端每次请求可能覆盖它；文案必须说明这一点。上游客户端请求参数不由 FlyEnv 拦截或重写。grammar、JSON schema、复杂采样器顺序、DRY/Mirostat 本次不表单化。

## 7. 额外启动参数的解析、冲突与文件依赖

### 7.1 输入与执行

提供多行输入框及示例，支持 `--flag value`、`--flag=value`、短别名、无值布尔参数、带引号路径和 JSON。输入值是参数片段，不是整条 shell 命令，不包含 executable。

使用专门的参数词法解析器，先得到 argv，再与结构化参数合并；不 `split(' ')`，不执行输入字符串。引号规则跨平台保持一致：双引号或单引号分组，只有必要的引号转义才消费反斜杠，Windows `C:\Models\...` 不被当作转义序列吃掉；普通参数值允许合法的 `&`、`#`、`$` 等字符。

不展开环境变量、通配符、命令替换、管道和重定向；单独的 shell 控制操作符给出“这里只接受参数”的输入错误，但不能误拒被引号包围的模板字符串。官方二进制继续通过 argv 传给 `serviceStartSpawn()`，不为高级参数改成 shell 拼接执行。

词法错误保留在当前页面草稿，但不能保存为正式配置；定位到未闭合引号/具体行。词法正确但语义尚未验证的参数文本可以保存，明确标记当前不能应用。保存的正式配置同时保留原始文本与可生成的规范化 argv 摘要，启动前重新解析并校验。

### 7.2 冲突规则

参数统一识别短/长别名、等号形式、正反布尔项。所有已知结构化字段只允许一个显式来源；不依赖参数先后顺序决定最后哪个生效。

| 情况 | 规则 |
| --- | --- |
| 表单字段为默认，额外参数指定该项 | 允许；表单只读显示“由额外参数设置”，提供定位文本与“移到表单”操作 |
| 表单和额外参数同时显式指定同一项，即使值相同 | 阻止应用，提示只保留一个来源 |
| 同一参数在额外文本里重复，或开关正反同时出现 | 普通单值参数报冲突；help/模块规则明确允许重复的累加型参数保留顺序 |
| 在额外参数填写 `--mmproj` | 允许；解析为与表单相同的有效文件引用，显示来源，执行同样的文件检查与依赖追踪；不能绕过关联规则 |
| `--no-mmproj` 与有效 mmproj 同时出现 | 报冲突，要求明确仅文本或指定投影 |
| `--cache-type-k`、`--no-mmap` 等扩展项 | 当前运行时支持且没有显式来源冲突时允许 |

受 FlyEnv 服务管理的参数不能在这里覆盖：主模型及替代模型来源、host、port、认证、FlyEnv 管理的日志路径，以及会进入 Router 或只打印信息后退出的模式。列出具体参数与别名，错误提示引导到对应服务/模型设置。这样健康检查、PID 和页面显示始终与实际服务一致。

对能够改变关联关系的已知文件参数，如 mmproj、draft、模板文件，统一生成 `ModelFileRef` / 运行依赖；不能只在表单路径上检查，遗漏额外参数的引用。

未知的新参数可以输入和保存，若实际 help 明确列出则按该选项边界解析；无法确认语法时标为“未验证”，不得因值以 `--` 开头就把它误认作另一个旗标。第一版只对明确识别的选项与语法生成“可应用”结果；词法正确但无法可靠完成语义解析的配置可保存为未验证状态，保留原文并阻止应用，避免虚假的通用支持。

投影模式为“未配置”时，额外参数中的 mmproj 可成为唯一有效来源，界面随之展示“使用投影文件，来源：额外参数”；模式为用户显式选择的“仅文本”时，额外 mmproj 报冲突。两者不依赖隐藏的参数顺序决定结果。

### 8.4 保存、应用与编辑保护

- **保存**：校验结构、文件字段和输入语法后写入配置；运行时兼容未知不阻止保存，但已知不支持项明确保留为“无法应用到当前版本”。保存不自动启停。
- **保存并重启**：仅当前服务选中的模型且服务正在运行时显示；完整预检通过后保存，再调用通用 `restart()`；若服务已停，则提供“保存并启动”。
- 编辑其他模型时只有保存，不提供可能误启停当前服务的按钮；另有明确“设为服务模型”动作，复用已有切换确认和控制器。
- 配置 revision 与当前运行快照不同，显示“已保存，待重启”；不能只比较页面 dirty 状态。
- 页面修改未保存时，切模型、切页签或离开页面触发“保存 / 放弃 / 继续编辑”；自动完成的后台操作不弹这些确认。
- 保存失败保留输入和旧正式配置；“恢复默认”只改当前编辑模型的草稿，再由用户保存，不影响其他模型或公共网络设置。
- 文件暂不可达时允许保存为明确“不可启动”的配置，不能显示校验通过；保存与“准备启动”的成功定义分开。

### 8.5 命令预览

命令预览由实际 fork 命令生成器返回，与启动共享构建逻辑。展示运行时、主模型、投影、draft、cwd、参数来源和未验证项；默认折叠，有错误自动展开检查摘要。

提供“复制当前平台命令”和“查看参数列表”。Windows 使用明确标注的 PowerShell 显示格式，Unix 使用 POSIX shell 显示格式；正确处理空格、单引号、反斜杠和 JSON。显示用的引号不传回 argv；复制命令只是显示出口，不承担内部执行。

编辑时预览标记“未保存草稿”；运行中可切“本次运行 / 下次启动”，实际运行快照不能被后续编辑覆盖。预览失败不影响已经保存的配置。

运行快照由 fork 维护；应用重开或 worker 重建后若无法可靠恢复，不得用最近保存配置伪造“本次运行”。此时显示“现存进程配置未确认”，恢复旧配置功能不可用；只展示已可靠取得的进程信息。无法确认运行依赖期间，运行中的该模块文件删除入口保持禁用，正常停止再启动后重新建立快照，不额外增加一套磁盘进程状态账本。

不新增敏感 IPC 通道，不改变现有认证保存机制；预览不读取或展开 key 文件内容。若将来增加直接携带秘密的参数，再按该字段的实际需求设计显示规则。

## 9. 兼容性检查与命令构建

### 9.1 三层检查

1. **本地结构检查**：类型、值范围、JSON、参数词法、重复来源和文件模式；不启动进程。
2. **fork 预检**：文件解析、可读性与身份、所选二进制 help、必要设备检查、字段组合与 argv 构建；不加载大模型、不占用服务端口。
3. **实际启动**：加载模型和辅助文件、现有 health 检查；成功后附加观察运行能力。

help 缓存仅保留在模块会话内，按二进制规范路径、版本身份、大小和 mtime 区分；替换二进制后失效。设备列表与驱动相关，单独短期缓存并提供刷新，不把某次设备查询结果永久写入模型配置。

`RuntimeCapabilities` 保存 flag、aliases、arity、已解析枚举、明确默认值和来源。不做“所有以 -- 开头的 argv 都是选项”的扫描，否则模板/JSON/值容易被误判。已知描述表负责语义，help 负责该构建的存在与语法；解析不清楚时返回未知，不能直接判定支持。

### 9.2 检查结果分级

| 等级 | 例子 | 保存 | 应用 |
| --- | --- | --- | --- |
| 输入错误 | JSON 错误、引号未闭合、重复参数来源 | 正式配置不保存，保留页面输入 | 阻止 |
| 明确无法启动 | 文件缺失、明确不支持的 flag/枚举、已证实的模型不匹配 | 可保存并标记不可启动 | 阻止 |
| 无法完成必要检查 | help 超时、运行时不可读 | 可保存 | 阻止本次应用，可重试检查 |
| 兼容性待验证 | 外部投影来源未知、模板语义未知、后端组合未验证 | 可保存 | 非阻塞提示，运行时加载验证 |
| 提示信息 | 量化可能降低精度、采样可被请求覆盖 | 可保存 | 允许 |

未安装运行时情况下可保存草稿配置，不能生成“已验证兼容”的命令。对已保存但新版本不支持的字段，不静默丢弃、不自动降级功能，明确要求恢复默认或改用支持版本。

### 9.3 一条命令生成链

`服务设置 + 主模型 profile + backendOverrides + 额外参数 → 有效字段与来源 → 文件依赖解析 → 能力校验 → PreparedLaunch`

预览和启动调用同一函数，避免 UI 自行拼另一套参数。正式启动使用调用瞬间的深拷贝快照；`startExtParam` 不再通过可变的公共 profile 组装半旧半新的配置。fork 在真正 spawn 前复检必要文件和二进制状态，不把缓存预览结果当作长期授权。

当存在会改变启动行为的继承 `LLAMA_ARG_*` / `MTMD_*` 环境值时，预检应显示相关覆盖来源；关键服务管理项必须与本次准备的参数一致。实现时沿用现有 EnvSync 边界处理，不新增一套用户环境管理器，也不能宣称 argv 预览涵盖未识别的环境影响。

## 10. 模块边界与操作契约

### 10.1 状态所有者

| 状态 | 所有者 |
| --- | --- |
| 正在编辑哪个模型、草稿表单、展开分组、未保存提示 | 当前挂载的 Vue 页面及编辑器 |
| 服务配置、每模型 profile、下载文件与关联关系 | `LlamaCppController` 单例，通过 reactiveBind 暴露，Storage 持久化 |
| 预检/预览请求、配置应用进度、notice、终态、重入与 IPC 释放 | 模块 controller 内具名 operation |
| 二进制能力与文件检查、启动快照、子进程、PID、端口、退出确认 | fork LlamaCpp 模块 |
| 通用启停、重启与服务状态交互 | 现有 ModuleInstalledItem；参数在模块 aside 注册 |

不以通用 loading map 替代操作 owner；编辑器调用控制器命令，不注册长操作 IPC、不自行派发终态通知。

### 10.2 操作契约

| 操作 | 起点与寿命 | 中间事件 | 终态与重复调用 | 服务交互与清理 |
| --- | --- | --- | --- | --- |
| 能力检查 / 命令预览 | controller 收到模型+草稿+运行时快照；请求至结算 | 检测运行时、解析依赖、检查参数 | ready / invalid / failed；相同请求复用，后来的请求使用 generation，旧响应不能覆盖新结果 | 不启动服务；离页后忽略视图写入，IPC 在真实终态释放，help 子进程超时清理 |
| 保存配置 | controller 收到不可变配置快照，直到 Storage 完成 | validating / saving | saved / failed；串行写入，重复点击复用本次 promise | 写成功再更新正式域状态；失败保留草稿，不影响运行服务 |
| 保存并应用 | controller，从预检至通用 restart/start 结算 | validating / saving / stopping / starting / observing | success / failed / partial / unknown；同一模块单飞，与模型切换共享互斥范围 | 复用 ModuleInstalledItem 生命周期；停止未确认不得启动；订阅与 notice 由 controller 清理 |
| 下载后关联 | 已有下载 operation + 显式用户保存关系 | 下载 progress；之后关联 saving | 下载与关联各自结算，不合并成可重复的整段重试 | 下载失败不关联；关联失败不重复下载；页面卸载不中断下载 |

IPC 沿用现有 `code: 200` 作为中间进度、`code: 0` 作为成功结果及现有错误协议；底层启动 PID/日志事件均不是整体应用成功。操作只在真实终态释放 listener，健康检查或停止结果未知时不得用 UI loading=false 推断进程已退出。

## 11. 失败边界与部分完成

| 步骤 | 类别 | 失败影响及保留事实 |
| --- | --- | --- |
| 主模型/显式投影/draft/模板读取 | 应用的必要依赖 | 阻止依赖它的启动；不影响其他模型配置与独立下载 |
| 必要参数支持与正式预检 | 应用的必要依赖 | 失败时不先停正在运行的旧模型 |
| 配置写入 | “保存并应用”的必要依赖 | 写入失败不启停；内存旧正式状态保持 |
| 已写入后停止失败 | 应用的必要依赖失败 | 报“配置已保存，应用未完成”；保留旧运行快照，不再次保存或强启新服务 |
| 停止成功后新配置启动失败 | 应用失败 | 保留新保存配置，标明服务未按新配置运行；不能宣称保存失败 |
| 独立候选的元数据解析 | 独立单项 | 标记该文件未识别/损坏，其他候选继续 |
| 推荐提示、启动后能力观察、预览显示、通知 | 附加动作 | 只报告自身失败，不推翻下载、保存或启动结果 |

“保存并应用”失败后不自动重放启动。确认新进程已清理后，提供“恢复上次成功运行设置”动作，先展示将恢复的模型与参数，再由用户执行。controller 通过 `startExtParam` 提供一次性旧启动快照并调用通用 start，不覆盖新保存配置，不新增私有 spawn 工作流；故恢复后依然显示新配置“待应用”。没有可靠旧快照或清理结果未知时禁用恢复。

现有“切换模型”的自动回退保持原有有界行为，但须使用真实旧启动快照，并先确认失败的新进程已清理；不得把新保存配置误当旧运行配置。配置应用与切换回退共享操作互斥，不互相触发恢复循环。

恢复结果分别报告：“新设置应用失败；旧配置已恢复运行”或“恢复失败，当前未运行/状态未知”。恢复成功也不把本次应用标成成功；清理或停止未确认时保持 unknown，不盲目再次启动。

## 13. 建议实施顺序

完整目标按四个可验收阶段推进，不将后半段设置描述为第一阶段已支持：

1. **配置与关联闭环**：V2 迁移、每模型保存、文件角色、托管/外部 mmproj 关联、统一 prepare、启动传参与引用保护。能直接解决 #905 的核心问题。
2. **参数扩展与可见性**：额外参数解析/冲突、受控参数、文件依赖、命令预览、运行与待启动快照、预检操作 owner。高级用户可使用当前运行时支持的其他 flag。
3. **常用高级表单**：资源、性能/KV、多模态细项、模板/思考、采样默认值，统一默认语义和能力禁用状态。
4. **投机解码与组合验收**：普通 draft、主模型内 MTP、基础 ngram 的专用表单和依赖校验，验证跨版本/后端切换及应用失败恢复。

建议在阶段 1、2 验收后可先发布一个解决图片输入与扩展参数的版本；是否拆分发布由评审决定，完整方案中的表单范围不因此消失。真实 Qwen/CUDA 验收是发布支持声明的依据，不能由文档和 mock 检查代替。

## 14. 验收清单

### 14.1 #905 用户流程

1. 下载 `Qwen3.5-9B.Q4_K_M.gguf` 与 `mmproj-BF16.gguf`。
2. 主模型配置中看到候选，用户确认关联后保存。
3. 命令预览出现一个 `--model` 和一个 `--mmproj`，两者路径正确。
4. 启动后健康检查通过；发送最小文字请求与一张测试图片请求，确认该实机组合可处理输入。
5. 停止、重新启动、重启 FlyEnv 后，文件关联和每模型设置均保留。
6. Cline 指向当前 Base URL / 模型别名完成图片请求；若客户端格式有差异，分别记录服务器最小请求与 Cline 结果，不能混为启动缺陷。

### 14.2 配置、文件与参数

- 两个主模型分别保存不同 mmproj、上下文和模板；切换后互不串值；仅切编辑对象不切服务。
- 多量化主模型共享一个 projector；多个 projector 候选不自动绑定；没有投影时文字模型仍可启动。
- 外部文件含空格、中文、单引号、反斜杠时正常解析；源文件删除/替换后不偷偷降级或换同名文件。
- 损坏辅助文件只影响该候选；被运行快照占用的文件不能通过配置解除关联后绕过删除保护。
- 旧 schema 正常迁移、重复迁移、Storage 写失败与指纹变化均保留原事实。
- 额外参数覆盖默认字段、显式重复、短别名、等号、负数、JSON、带 `--` 的值、正反布尔、可重复参数分别验证。
- `--mmproj` 来自文本时也纳入依赖与删除保护；受控 host/port/model 参数不能改变实际服务管理目标。
- CPU / CUDA / Vulkan / Metal 切换时不复用错误设备名；旧版不支持的字段保留且阻止错误应用。
- 预览与实际 spawn 的 argv 相同；平台命令复制正确转义；预览草稿不覆盖当前运行快照。
- 新增高级项默认不产生额外 flag；0/-1 等合法值不丢失；采样默认不误称强制客户端生效。

### 14.3 生命周期与失败

- 重复点击保存、预检、应用只启动一项操作；保存与模型切换并发不会混合快照。
- 离页再进入能恢复操作进度；旧预览响应不能覆盖新模型或新运行时结果；终态 IPC 释放。
- help 超时/不可读、文件失效和明确不支持参数均在停旧服务前失败。
- 应用重开后现存服务缺少可信快照时显示未知，不把下次配置当作实际运行配置，也不允许删除未确认的运行依赖。
- 配置已存但停止失败、新启动失败、用户执行旧配置恢复失败分别报告；设置应用失败不自动重试启动，未知 PID/清理状态禁用恢复。
- 下载成功后关联写失败不重放下载；启动成功后能力 API 失败不停止服务；通知失败不覆盖主结果。
- 模板文件和草稿模型不会被当作独立 companion 服务管理。

实施时采用模块内聚焦回归验证和现有插件契约/renderer operation 检查，不恢复已清理的大量一次性全仓测试脚本。本轮仅文档，不运行构建或产品测试。

## 15. 评审时需要重点确认的取舍

本提案已经给出推荐值，以下是可调整的产品边界，不是实施中的隐含默认：

1. 默认采用“推荐候选后确认”，不静默关联；投影支持引用用户选择的外部文件。
2. 保留五个顶层页签，模型配置统一放在设置页，通过服务/模型列表快捷进入。
3. 普通保存不自动重启，当前运行配置与待应用配置分别显示。
4. 额外参数可补充表单默认项，包括 mmproj，但任何一个显式字段只保留一个来源，并纳入同一校验链。
5. 首轮不把所有专用推理参数表单化；投机解码先支持普通 draft、主模型内 MTP 和基础 ngram，其余保留扩展入口。
6. 建议分阶段验收、允许先发布关联与额外参数闭环；不在未验证实际模型/运行时组合前声明全面多模态支持。
