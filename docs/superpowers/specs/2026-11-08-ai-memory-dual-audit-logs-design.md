# AI Memory 双调用日志设计

## 目标

AI Memory 的 MCP 调用同时产生两类记录：

1. FlyEnv MCP 的 `mcp/audit.log` 持久化简版审计，便于统一查看客户端调用。
2. AI Memory 新增「调用记录」顶级 Tab，展示详细的内存日志，用于搜索优化、调试和结果验证。

详细日志保留搜索词和记忆摘要，但完整记忆正文 `content` 必须排除。详细日志不持久化，FlyEnv 退出后清空。

## 架构与归属

简版文件审计由 `MCPServer` 的插件工具分支写入。该分支能看到所有 MCP 插件调用终态，包括参数校验失败、工具禁用、审批取消、执行失败和未知结果。文件日志继续由 `MCPAudit` 管理。

详细内存日志继续由 `PluginMCPRegistry` 和 `PluginMCPAudit` 管理。插件注册层负责生成经过字段白名单筛选的调用快照，避免原始请求或 worker 返回值绕过脱敏。

不新增 Pinia 状态、共享配置或持久化模块数据。现有 `MemoryController` 负责调用记录 IPC 和页面状态，新组件只负责展示。

## 简版 MCP 文件审计

每次 AI Memory MCP 工具调用追加一条 JSON 记录，包含：

- 时间、工具名、插件 ID。
- 客户端名称和版本（客户端自报）。
- 成功状态、结果类型和错误码。
- 记忆 ID、request_id、revision 和耗时。

简版日志不记录搜索词、记忆摘要或完整正文。文件写入失败由 `MCPAudit` 隔离，不改变工具结果。

`MCPAudit` 不再把已注册插件工具重定向到内存日志；插件分支只写简版文件日志，详细日志仍由插件注册层记录一次，不能重复计数。

## 详细调用记录

覆盖 `flyenv_memory_search`、`get`、`store`、`update` 和 `forget` 的全部调用终态。

通用字段包括时间、工具名、插件 ID、客户端、耗时、结果、错误码，以及安全的结果元数据。

搜索记录包括：

- 完整 `queries`。
- scope、项目路径、类型、主题、标签、状态、全局/过期包含选项。
- limit、分页方向和游标是否提供；不依赖完整游标进行诊断。
- 命中数量、truncated、next_cursor 是否存在、unregistered、项目候选和警告。
- 命中记录的 ID、标题、摘要、revision 和相关公开元数据。

读取、写入、更新和删除记录包括：

- scope、项目路径、记忆 ID、request_id、expected_revision 和实际 revision。
- 标题、摘要、主题、标签、类型、状态、置顶和过期时间等元数据。
- 更新原因和变更字段名。

记忆摘要需要保留。完整正文必须排除：任何请求、响应、错误、警告或嵌套对象中的 `content` 字段均不得进入内存日志。传输错误不得直接保存原始错误文本；使用结构化错误码，避免错误消息意外携带正文。

沿用最多 200 条的有界内存队列，新记录淘汰最旧记录。这里的“所有操作”指五种 MCP 工具的所有终态，不表示无限保留历史。

## 调用记录 Tab

在「记忆 / 接入 Agent / 维护」之外新增「调用记录」Tab：

- 表格展示时间、操作、客户端、结果、耗时和命中数。
- 每行可展开查看结构化详情，搜索词、过滤条件、结果摘要和错误码应可直接检查。
- 进入 Tab 时加载，支持手动刷新。
- 明确提示日志仅在本次 FlyEnv 运行期间保留。
- 删除维护页旧「最近诊断」区域，保留并复用 `plugin:diagnostics` IPC 作为新 Tab 的数据源。

不增加自动刷新定时器、持久化、导出或独立清理流程。

## 失败边界

用户要求的记忆操作结果是主操作；两类日志均为附加观测动作。

- 文件审计失败不得拒绝、覆盖或重放已完成的记忆操作。
- 内存审计失败同样不得改变工具终态。
- 参数校验、权限和审批失败必须记录自己的真实结果，但不触发 worker 执行。
- 已成功写入的记忆不能因为后续日志失败被报告为失败。

## 验证

重点测试：

1. 插件调用写入同一个 `mcp/audit.log`，简版记录不含 queries、summary 或 content。
2. 详细日志保留搜索词、搜索过滤条件、命中摘要和无命中诊断数据。
3. store/update/get 等嵌套请求与响应中的完整正文均不进入详细日志。
4. 成功、失败、取消、未知和禁用终态均记录，且不重复。
5. 内存队列保持 200 条上限。
6. 文件或内存日志失败均不影响已提交操作。
7. 新 Tab 的加载、详情展示和旧维护区域移除通过插件构建及相关测试。
