# AI Memory 球形体积光雾问题分析与实现方案

日期：2026-11-10

## 1. 目标与范围

在现有神经记忆体的球形空间内部增加低密度、可缓慢流动、局部被照亮的金色体积雾，让节点和环架处于同一个有内部介质的空间中。保留清晰的近景结构和可探索的记忆节点。

预期效果是：中心暖白金，中层琥珀金，外围自然消退；内部存在疏密、空隙与少量丝状变化；拖动观察时能感到雾处于不同深度。雾应连接现有结构，不能遮成不透明烟球、实体球壳或覆盖整个画面的金色蒙版。

范围限于 `.worktrees/ai-memory-neural-preview/tmp/ai-memory-neural-preview/` 独立预览。继续使用 Three.js WebGLRenderer，不迁移 WebGPU，不增加后端。保留八类、160 条模拟记忆、语义关系、分类与单点聚焦，不修改正式插件、MCP、持久化或服务生命周期。

本方案中的采样数、颜色、密度和性能预算均为建议起点，需在实际画面与设备上确认。

## 2. 当前缺口与技术难点

### P1 光点与线条之间仍缺少连续的空间介质

现有 Points、LineSegments、带状主轨和 Sprite 可以表达节点、连接、光晕和能量，但没有定义整个球内每个位置的雾密度。增加粒子数量不能自动产生连续体积。

### P2 FogExp2 和 Bloom 不能替代局部体积雾

当前 `scene.ts` 中的 FogExp2 属于距离雾设置。自定义 Shader 的实际表现还取决于是否接入对应雾计算，不能因 Scene 上有 fog 属性就认为所有材料已经受到雾影响。Bloom 则从已渲染的亮部扩散，不能单独描述球内疏密和沿视线的吸收。

### P3 当前主体大量使用透明加法材质

普通节点、关系线、主轨、流光、中枢光晕和选中边很多都设置了 `depthWrite: false`。仅在最后读取一张普通深度图，不能知道所有透明节点和线段位于雾中的哪个深度。

如果先渲染全部结构，再在最前面画一层透明雾，近处和远处线条会被同样覆盖；如果给每条线各自叠加雾颜色，密集处又会重复累加雾，产生不合理的亮斑。

### P4 真正的体积效果会增加 GPU 成本

每个覆盖球体的像素都需要沿射线多次采样密度。若再让每个记忆节点参与散射、阴影或多次反弹，成本会迅速增大。需限制分辨率、步数和照明区域，并为透明结构的衰减计算单独计入成本。

## 3. 路径比较与推荐

1. **多层雾片或 Sprite。** 可快速形成气氛，成本较低，但交叉、侧面和近景容易暴露片状结构。本轮不作为主要交付，也不将雾片降级称为真正体积雾。
2. **球内密度场加轻量光线步进。** 用三维密度纹理定义雾，沿相机射线积累透射与发光；给透明结构补充到自身深度为止的雾衰减。推荐采用，能适配现有加法主体。
3. **完整物理体积散射与大量动态光源。** 能力更强，但目前没有必要引入多次散射、体积阴影或每节点照明。

推荐方案属于受控的发光介质近似：真正沿三维射线积分密度和透射，照明采用少量艺术化能量场，不宣称物理精确复现电影。

## 4. 球内密度场

### 4.1 空间归属

新增预览内部的 `NeuralVolume` 所有者，挂接到与记忆体相同的根坐标系。体积中心位于主体原点，初始半径取装饰主体保守半径的约 90%–95%。不把雾作为可见球面 Mesh 绘制。

雾跟随整个记忆体的拖动与根旋转，不跟随三个陀螺仪运动组各自旋转。已有环架和节点在同一个雾场中运动。不要同时在世界坐标和局部坐标各自累计一次旋转。

相机和被渲染片元的位置都通过同一个世界到体积局部空间矩阵转换。将局部位置除以体积半径得到归一化坐标；密度采样和光学路径长度都使用这个归一化空间，避免镜头缩放或单位选择无意改变雾浓度。

### 4.2 密度构成

密度由球形边界包络、低频三维噪声和较弱的细节噪声相乘得到，最终约束在 0–1。默认低频变化占主导，保留大块稀薄区域，避免浓密棉絮状云团。

球面附近约最后 15%–25% 半径使用平滑衰减，球外密度严格为零。内部不是只有球面上一圈雾，也不是所有位置同样浓。可用少量缓慢的坐标扭曲形成丝状延伸，但不添加高速湍流。

首次使用确定性生成的 64³ 单通道、可周期平铺的三维噪声纹理，允许复用同一纹理的两个尺度。噪声坐标可循环，球形密度包络独立计算，检查平铺边界没有切面接缝。生成和上传发生在初始化，不在每帧重新计算或上传三维数据；使用线性数据采样，不标记为 sRGB 颜色纹理。

密度参数与种子属于装饰效果，不从记忆内容推断情绪、重要性或知识关联。

### 4.3 动画与减少动态

采用已有 `motionTime` 驱动低速噪声坐标平移和很弱的形变，时间推进与现有暂停规则一致。不使用逐帧随机密度，也不依赖带历史缓存的时间降噪。

减少动态开启时冻结雾形与能量变化，保留静态体积。页面隐藏时停止推进和渲染；恢复时不得因墙上时间跳变而突然翻动。

## 5. 低密度暖金发光与透射

### 5.1 先用简单照明建立方向

保留一个中心暖白金能量区，加上最多两个较弱的中层琥珀金能量区。能量使用局部高斯分布或其他有界平滑函数衰减，底色很暗，避免整球均匀发亮。

这些区域明确属于装饰照明，不为 160 条记忆分别创建动态光源。第一版不计算环架投射的体积阴影，也不实现多次散射。

### 5.2 积分约定

在球内射线段上按从近到远积分。每步使用非负消光系数、密度和步长计算透射 `Tstep = exp(-sigma × density × stepLength)`；累计透射相乘。

每步向累计雾颜色添加“到这一步的透射 × 本步吸收份额 × 局部光雾颜色”。这里局部光雾颜色是艺术化的源函数，所有 RGB 在统一线性空间计算。这样改变采样步数时不会简单成倍增加亮度。

全局消光系数建议从归一化单位下的 0.10–0.18 起调。密度不超过 1、完整归一化球径不超过 2 时，整段透射不会低于约 0.70；这是初始低密度约束，不是最终画面实测值。默认应能透过球体看到后层结构，不能靠把雾调浓来掩盖结构不足。

先稳定密度和能量，再决定雾是否需要参与较强 Bloom。不要让整个雾团超过辉光阈值变成大面积亮球。

## 6. 与透明线条正确组合

### 6.1 为当前加法主体采用一致的近似

把画面分为两种贡献：沿相机射线积累一次的体积发光，以及每个节点/线段自身经过前方雾衰减后的发光。

概念上最终线性颜色为：`雾的累计发光 + 各结构片元的原有发光贡献 × 相机到该片元的透射`。结构原有的 alpha、关系权重、柔边和选中高亮继续保留，雾只额外调制其 RGB 贡献。

对现有透明加法主体，这允许近线清晰、远线柔和，不依赖普通深度图去记录所有透明物体。该近似不负责一般不透明物体的遮挡或任意透明折射；当前预览没有这类业务对象。以后增加实体遮挡物时需另行加入深度截断，不能沿用“所有内容都加法相加”的假设。

### 6.2 结构片元只计算前方透射

通过共用的体积 Shader 函数，沿相机到片元的有限线段求与球的交区，再进行较少步数的密度采样。片元在球前方时不衰减，位于球内时积到片元，位于球后方时积完整球内段。

统一函数必须与体积 pass 使用相同的密度纹理、种子、坐标变换、时间、半径和消光参数。它只返回透射，不给每个结构片元重复叠加雾颜色。若球无交点或雾已关闭，直接返回 1。

覆盖清单包括：记忆节点、背景光点、普通关系边、带状主轨、流光、装饰细线、中枢环、核心/中枢 Sprite，以及选中边。普通 ShaderMaterial 使用共用片段；内置 SpriteMaterial 和 LineBasicMaterial 用预览内部统一适配器接入，并核对当前 Three.js 版本的 Shader 插入点与程序缓存键。

Points 可将当前点中心作为采样终点的近似；大 Sprite 应使用其面向相机平面上的片元位置，避免整个光晕得到同一个过粗的透射值。带状主轨使用展开前中心线位置作为终点近似，容许几像素宽度内的误差。

雾启用时停用同一场景的 FogExp2，避免额外施加一套不同的距离雾；已有纯美术深度排序衰减可以保留，但需要单独标定。关闭体积雾时恢复进入体积模式前的雾设置，不改变原始预览效果。

### 6.3 单独计算体积发光并合成一次

新增 `NeuralVolumePass`：用相机射线与球的入口/出口限定步进区间，在较低分辨率渲染目标中累计体积颜色及完整球段透射。相机进入球内时，将入口截断到当前视点，不能出现内外翻转或重复积分。

低分辨率结果的 RGB 存放已经沿射线积分的雾发光，A 可存放透射供调试。它不使用普通“颜色加 alpha”覆盖规则；合成 pass 只把雾 RGB 加到已逐片元衰减的场景颜色上。不能再次把整张场景乘一遍完整球段透射，也不能将透射 A 当成普通透明度使用。

当前页面使用黑色不透明 WebGL 基底，合成输出 alpha 固定为 1。背景仍由前一轮方案规定的黑底与全屏 CSS 氛围层提供，HUD 和 DOM 标签不进入体积 pass。

## 7. 后处理顺序与材质边界

当前源码已加入 `OutputPass`。推荐沿用并扩展为：

`RenderPass（结构已乘前方透射） → NeuralVolumePass（积分并合成雾发光） → UnrealBloomPass → OutputPass`

雾在 Bloom 前以线性颜色合成，统一输出后再由页面显示，不额外执行手写 sRGB 或 gamma 转换。官方体积云示例包含其独立直出方案的颜色编码，不能原样复制到这条 composer 链中。

雾的采样纹理、中间目标、合成材质、结构衰减适配器都由现有场景层统一 resize 和 dispose。不创建第二个 canvas、renderer 或独立动画循环。

在体积 pass 初始化失败时，必须同时关闭结构材料的雾衰减；不能留下“节点变暗但没有雾”的半启用状态。资源及材质变体准备完成前不启用效果；材质编译失败时恢复接入前的 Shader/钩子和缓存约定，而不只把一个 uniform 设为 0。关闭效果时同时跳过 pass 和片元密度采样，避免只隐藏颜色却保留成本。

## 8. 性能预算与降级

首次提供关闭、低、标准三档，参数属于预览局部视觉设置，不增加共享配置或持久化。标准作为试验默认档，实际默认值以测量和视觉对照决定。

- **标准：** 体积目标宽高从主绘制缓冲区各取一半，长边上限 960；球内约 40 步。结构透射约 8 步。
- **低：** 宽高各取约三分之一，长边上限 640；球内约 24 步。结构透射约 4 步。
- **关闭：** 跳过体积 pass，结构透射固定为 1，恢复原雾设置。

目标尺寸保持原宽高比，采样射线始终使用同一个相机与标准化 UV，不把降分辨率误当作修改相机视场。建议使用可用的线性半浮点渲染目标；所需纹理或目标能力不满足时直接关闭体积效果并保留既有预览，不新增另一套引擎。

第一版使用空间固定的微量采样抖动减轻条带，避免随帧随机闪烁；通过普通线性上采样合成。没有历史帧积累，因此不需要新增相机移动时的 TAA 清空逻辑。球边缘以密度软包络收敛，检查上采样后没有方块轮廓。

首次在当前设备上以“增加的持续帧耗时约不超过 3–4 ms”为调试预算，不将其当作未测量的性能承诺。GPU 计时可用时记录 GPU 数据，否则比较同条件下的帧耗时分布，并说明测量局限。

若标准档超预算，先切低档；低档仍明显影响交互则关闭。第一版采用手动档位，或能力检测失败的一次性关闭，不加入持续自动升降档，避免画质来回跳。降低质量时同步降低结构透射采样，不能只缩小体积目标而遗漏大批透明线条的采样成本。

## 9. 聚焦、拾取和页面生命周期

分类或单点聚焦时，将雾的消光系数及发光源强度一起平滑降低到全局的约 25%–40%，让当前节点和直接关系保持可读。两类计算共享同一焦点系数，不能只调低雾颜色却仍让节点承受全强度吸收。重置时恢复原参数。

雾不创建业务节点、不进入 Raycaster、不截获 pointer，不增加 DOM 关系或计数。使用调试区域进行画质对照，不把采样数、消光系数等技术参数放进正常记忆管理流程。

所有权合同：

- 所有者为当前 `NeuralScene` 内的 `NeuralVolume`，生命周期不超过当前预览页面。
- 初始化创建密度纹理和 pass；中间状态为局部的 enabled、quality、focus 系数和 motionTime，不新增后台操作或 IPC。
- 一次只保留一个有效体积实例。重复切换质量更新同一实例资源；快速切换只应用最新档位，旧的延迟尺寸回调不得复活已销毁目标。
- 页面隐藏暂停，减少动态冻结密度与照明变化；resize 更新目标尺寸及相机参数，销毁释放全部纹理、目标、pass、材质和观察器。
- 没有服务或伴随进程，不新增 Pinia、跨页面 singleton controller、Storage 或共享配置。没有模块边界例外授权。

## 10. 建议文件分工

以下新增文件只放在预览目录，不写入 FlyEnv shared 工具：

- `volume-model.ts`：确定性密度数据、球边界、参数约束及解析射线球交；与 WebGL 无关的部分便于独立验证。
- `volume-shader.ts`：共用坐标转换、密度采样、消光和局部照明函数；明确线性输入与归一化长度约定。
- `volume-material.ts`：结构透射的统一接入和恢复，覆盖自定义材质、Sprite、普通环及选中边。
- `volume-pass.ts`：半分辨率积分与一次性颜色合成；拥有中间渲染目标和合成材质。
- `volume.ts`：`NeuralVolume` 的配置、启停、质量、聚焦和资源生命周期。
- 修改 `scene.ts`、`entity-scene.ts`、`edge-material.ts`、`ribbon-material.ts`：绑定共用雾参数，接入所有相关图层，安排 composer 顺序与销毁。
- 必要时调整 `main.ts` 和现有 capture 驱动：局部质量控制、固定时间截图及降级验证，不改变记忆业务模型。

文件边界可按实际代码规模合并；上述职责不能散落成多个互相不同步的密度函数或参数副本。

## 11. 分阶段实施和失败边界

1. **建立无雾基线。** 固定模型、相机、时间和输出设置，记录全局、分类及单点截图和至少 10 秒性能数据。
2. **验证球内静态密度。** 暂时仅检查雾贡献，确认球边界软、内部有空隙、球外为零。该阶段不能宣称已完成与透明结构的空间融合。
3. **接入结构透射与一次合成。** 用前、内、后三个已知位置的亮点/线段验证，不依赖普通透明深度图。通过后再评审真实记忆体画面。
4. **调整暖金照明和低速流动。** 只使用少量能量区，完成减少动态、聚焦和返回。
5. **测量档位并验收。** 对照标准、低、关闭三档，确认降级能同时去掉雾发光与结构衰减，现有交互继续可用。

密度、坐标与结构合成正确是完整体积效果的必要依赖。初始化或材质接入失败时应关闭整套雾并提示局部效果不可用，保留已加载的记忆预览；不能把仅有蒙版或部分变暗的状态当作成功。

单个诊断图或视频导出失败不重建用户场景，不触发业务重试。着色器、拾取和资源泄漏问题必须处理；不能用增加噪声、曝光、采样步数或临时安装依赖掩盖实际错误。

## 12. 验收标准

### 视觉

- 雾填充球内不同深度，外缘自然消失，不在球外积累雾密度或吸收；允许统一 Bloom 带来的柔和辉光外溢。能看见内部空隙，始终没有实体球壳。
- 核心附近有暖白金光感，中层为琥珀金，外围暗；长距离观察时仍能辨认环架和分类网络。
- 旋转和缩放不会暴露贴片；相机进入球内没有内外翻转、亮度跳变或突然遮满屏幕。
- 前层线条较清晰，后层适度衰减；没有重复雾亮斑、整体二次变暗或与线条脱节的前景蒙版。
- 连续观看至少 10 秒，雾缓慢流动且不闪烁；减少动态后画面稳定，分类和单点模式清晰。

### 技术与行为

- 密度确定性、有限且非负，球外为零；射线无交点、相切、相机在球内、片元在球前/球内/球后都有明确处理。
- 同一射线减小步长时，颜色和透射收敛，不随步数线性增亮；零消光得到透射 1 和零雾发光，只有源强度为零时允许保留吸收。关闭模式必须同时关闭两种贡献并恢复基线。
- 已知前/内/后结构的透射顺序正确；结构只乘透射，雾颜色全屏每条射线仅合成一次。
- 关闭模式恢复原基线且不再执行雾采样；中间 pass 失败不能残留片元吸收。
- 八类、160 条模拟记忆和 semantic 关系不变；拾取、详情、键盘、拖动、缩放和返回行为正常。
- 页面隐藏、减少动态、重复切档、resize 和销毁后的资源/回调行为符合所有权合同。

### 画面与性能证据

使用相同种子、相机、根旋转、时间、曝光、Bloom、内容区尺寸和 DPR 生成无雾/有雾对照，不能通过改变镜头来制造体积变厚的印象。至少比较 1440×900、1280×800 和一组窄屏内容区，桌面检查 DPR 1 与 2。

记录每档分辨率、体积步数、结构透射步数、帧耗时分布和当前设备条件。标准档没有通过测量时不宣称流畅，低档失败时交付明确的关闭降级。

技术检查通过后仍须人工查看截图与连续动画。首轮成果应是可开关、可比较的球内低密度光雾；它不代替前一轮主轨材质、中层结构和背景融合的验收。
