# Issue #938：Homebrew 语言版本更新方案

状态：按用户 2026-11-07 的两点反馈修订，用户已确认方案；现已按实施计划实现，证据见docs/superpowers/reports 中的实施报告，尚未执行真实包升级。

## 1. 用户确认的范围

- 只在“版本管理 → Homebrew”页提供更新入口；服务页不增加字段、按钮或更新提示。
- 不自动迁移关联设置、配置文件或扩展，不调整 PATH、别名、站点、启动组和已选版本。
- 点击更新先显示警告；用户确认后，停止相关服务，再执行升级。
- 升级成功刷新服务列表；升级失败给出失败提示与日志。
- 不自动启动或恢复任何服务，包括升级失败前已经停止的服务；后续设置、配置和启动由用户手动完成。

这取代上一稿“双入口、自动迁移、自动恢复”的建议。上一稿的配置备份/迁移、恢复记录、条件配置写入和自动修复均从本次功能移除。

首版沿用 macOS 当前 Homebrew 实例的 PHP/PHP-FPM 范围，PHP 验收后可复用数据和执行能力扩展其他语言。Static、MacPorts、其他 Homebrew 实例及数据库升级不在首版范围。

## 2. 当前问题

截图的 Homebrew 8.5.12 是配方可用版本；服务页的 /opt/homebrew/Cellar/php/8.5.7 是实际安装版本。当前 brewInfoJson 只保留可用版本、安装标记及配方名，不能表达“装了旧版，可更新”，操作只有安装/卸载。

现有入口包括 VersionManager/brew/setup.ts 和 ModuleHomebrewItem.runCommand。增加更新时必须统一包操作归属，避免复制第三套页面内异步流程。

## 3. Homebrew 页面与警告

Homebrew 页区分“已安装”和“可用版本”，只在可更新的已安装条目上显示“更新”；保留安装/卸载入口。已是最新、已固定、停用、不兼容或无法确认来源的条目显示相应状态，不提供误导性的可用更新操作。

服务页只接收正常的安装列表刷新，不增加任何展示字段或更新入口。

点击更新后，在对话框中展示配方、已安装 → 目标版本和将停止的相关服务。建议警告正文：

> 更新会先停止相关服务，并可能改变版本和安装路径。更新后的配置文件、扩展及环境变量等关联设置需要您手动处理，服务也需要手动启动。是否继续？

按钮为“取消”和“确认更新”。取消时不停止服务、不执行命令、不修改设置。目标若跨 PHP 系列，在确认内容中明确标识；不自动改成另一个版本化配方或更换 tap。既然本次不负责配置兼容迁移，升级以用户确认的同一配方实际目标为准，不再把同系列作为自动配置迁移的前提。

如果新版本已经安装、Homebrew 不认为该配方过期，不再提供无意义的更新操作；服务页仍保留旧安装条目时，由用户通过现有界面选择需要的版本。

运行期间只显示“正在停止相关服务”“正在更新”和日志；可以离开页面，返回后继续查看。不开配置迁移向导，不新增恢复操作菜单。

## 4. 数据与目标识别

- 根据 brew info / outdated 获取实际安装版本、可用版本/revision、固定状态及更新资格；不以字符串大小判断版本。
- 配方身份包含真实 brew 路径、prefix/Cellar、full_name、tap 和必要的安装收据来源。Homebrew 专用数据放在 Homebrew 模块目录，不加入通用 SoftInstalled。
- 相关服务通过该 Homebrew 实例、Cellar 中的实际安装路径及配方归属识别，包括该配方下所有相关已安装 keg；不能仅凭 PHP 名称或版本号停止其他来源的服务。
- 只停止 FlyEnv 已管理且可确认身份的实例。无法确认必须停止的实例时，阻止当前更新并解释原因；列表中其他独立配方仍可正常查看和操作。
- 确认后、停止前重查更新资格和目标。目标、来源或需停止的服务集合变化时，更新对话框信息并重新确认；不能沿用过时快照静默执行。

不采集、比较或迁移 php.ini 正文、扩展配置、站点绑定和启动组引用。旧路径可能失效是警告覆盖的用户后续处理事项，不以自动修复为更新成功条件。

## 5. 执行流程

1. **检查**：读取当前配方状态，确定目标版本和相关服务，准备确认内容；失败时未发生停止或升级。
2. **确认**：用户明确点击“确认更新”。
3. **受理**：控制器固定本次请求，取得该 Homebrew 实例的包操作串行入口，执行前复核目标；重复点击复用同一任务。
4. **停止相关服务**：复用 ModuleInstalledItem.stop() 和现有 fork 生命周期。所有必须停止的相关实例均确认停止后才允许升级；停止失败则提示“更新失败：无法停止相关服务”，不运行 brew。已停止的实例保持停止，不自动恢复。
5. **升级**：fork Brew 模块使用已确认 brew 的绝对路径和参数数组执行 upgrade --formula <完整配方名>，单次执行，不加 sudo、不强制 unpin、不自动换源，不拼接任意 renderer shell 文本。
6. **成功**：brew 正常退出后刷新 Homebrew 数据和对应服务安装列表，提示“更新成功，请手动完成相关配置并启动服务”。不以网站、配置或扩展是否可运行作为本次包升级的额外完成条件。
7. **失败**：brew 非零退出或执行异常则提示“更新失败”，保留错误/输出日志；不自动重试、不回滚、不启动服务，也不声称 Homebrew 已恢复原状态。
8. **清理**：确认真实执行终态后释放任务状态和监听资源。

为避免确认后由本次命令自动刷新元数据改变目标，可在该子进程范围设置 HOMEBREW_NO_AUTO_UPDATE=1；Homebrew 支持默认询问时，在 FlyEnv 已确认的前提下使用其非询问模式。不修改用户 shell 配置，不增加备份/迁移/清理旧版本操作，包安装与依赖处理沿用 Homebrew 行为。

Homebrew 可能更新依赖或依赖方，指定一个配方不等于只改变一个目录。执行前检查潜在影响与 FlyEnv 运行实例；需额外停止其他受管实例时必须纳入确认。无法确认必要停止范围，或计划包含首版未支持的数据库变更时，当前任务不自动执行。该检查只用于避免更新正在使用的安装，不扩展成依赖配置迁移。

## 6. 刷新不等于自动修改关联

成功后的刷新只更新安装清单和界面状态，不能借刷新间接修改用户设置：
- 不因旧路径消失就自动选中另一个版本、重写 config.server.current 或保存新的 PATH/别名。
- 不修改启动组 versionPath、站点 PHP 版本、旧版本备注或配置文件。
- 不调用会创建默认配置的 PHP getIniPath 作为刷新步骤；新版本配置由用户后续设置/启动行为按既有规则处理。

现有 Module.applyInstalledVersions 会调用 resetCurrentVersion（PHP 当前被排除）及备注同步；实施时必须核对刷新副作用，确保更新触发的刷新符合上述要求。将来扩展其他语言时同样不能通过既有自动选择逻辑悄悄接管关联。

刷新失败属于附加步骤失败：提示“更新成功，但服务列表刷新失败，请手动刷新”，保持升级成功事实，不把它当作 brew 失败，更不能重新升级。

## 7. 操作归属和最小并发约束

- 页面只保留对话框/筛选等 UI 状态，展示控制器状态并提交用户确认。
- Homebrew 目录中的单例控制器经 reactiveBind 暴露状态，拥有请求快照、检查/停止/升级/刷新、进度、通知、防重、终态与监听清理；不新增 Pinia 或 config.setup 状态。
- fork Brew 拥有真实命令进程、输出和实际终态；页面终端只展示日志，不拥有进程生命周期。
- 复用既有服务生命周期，停止仍走 ModuleInstalledItem.stop()；不引入独立的服务启动/恢复方法。
- 同一 Homebrew 实例的包变更串行，与既有安装/卸载共用执行入口。升级期间受影响安装的新 start/restart 需在 main 最终受理处阻挡，覆盖服务页、启动组和 MCP；仅禁用 Homebrew 按钮不足以避免并发启动。
- 先等待已受理的相关生命周期请求结算，再确认停止结果。阻挡只针对相关安装，其他服务可继续运行；停止请求沿用原生命周期，不需要为自动恢复扩展 start 的专用上下文。
- 页面卸载不取消任务。code:200 等进度不是终态；重复终态不能重复通知或发起第二次升级。
- 请求超时/断连时结果为未知，不能假报成功、直接释放仍运行的任务或自动重试。继续查询原任务/日志；只关闭日志窗口不终止升级。

不新增独立的配置迁移事务、持久恢复日志或跨重启自动修复框架。应用退出和命令取消复用已有进程/任务收口，必须区分停止观察与实际终止子进程，不能在 brew 仍修改安装时开启第二次操作。

## 8. 实施与验收

先实现 Homebrew 元数据与页面更新状态，再完成单例控制器/fork 执行及停止链路，最后核对刷新副作用和真实前台交互。服务页不作为此次 UI 改动对象，配置/关联 owner 不增加迁移方法。

验收覆盖：
- 已安装旧版/已是最新/未安装/revision-only/pinned；core 与第三方 tap、不同 Homebrew 实例隔离。
- 只有 Homebrew 页有更新入口，服务页没有新增字段；警告展示实际目标，取消无副作用。
- 运行中先停止再升级；不运行的不多做停止；停止失败不执行 brew，已停止的服务不自动恢复。
- 退出码 0 时刷新列表，非零时提示更新失败；失败不自动重试或重启。
- 成功刷新前后 PATH、别名、站点、启动组、当前版本选择与配置文件保持原值。
- 刷新失败仍保留升级成功；重复点击、离页重入、迟到 IPC、并发 start/restart 和应用退出不造成重复进程/命令。
- 在隔离测试环境中验证真实 Homebrew 更新与服务停止；不修改开发者日常 PHP。文案覆盖中英文、深浅色和窄窗口。

本设计已用于当前实现；实施与验收边界见 docs/superpowers/reports/2026-11-07-homebrew-language-upgrade.md。
