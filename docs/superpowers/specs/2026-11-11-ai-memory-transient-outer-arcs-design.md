# AI Memory 外围弧带动态优化方案

日期：2026-11-11

## 1. 目标和范围

把外围长期存在的环架，改成少量有头尾、会沿轨道运动并逐渐消散的局部弧带。整体球形空间继续由节点、连接、内部结构和体积雾共同呈现，外围装饰不再持续描出一个封闭外壳。

本轮针对独立 Three.js 预览的外围装饰。保留核心主轨、分类中枢提示环、记忆节点和真实语义关系的现有职责；不把它们全部改成随机消失。体积雾、曝光、Bloom、OutputPass 和相机布局作为比较基线，不在同一轮重新调节。

## 2. 视频中可以确认的表现

外围较亮的轨迹是具有端点的弧带，部分由数条平行细线、横档和短电路组成。它们沿球形空间中的不同平面运动，有些覆盖较长角度，但没有始终完整显示整圈。

连续帧中，左下方的长弧逐渐收短、变暗；顶部弧带逐渐展开。各部分变化并不同步，表现为局部结构不断显现、推进和消退。弧段位置、可见长度、亮度与整体朝向都在变化，不能仅用整环刚体旋转解释。

视频较短，不能确认原作者是否使用随机生成，也无法反推出精确周期、数量或角速度。以下使用确定性随机与生命周期，是复现这种观感的工程选择，不是对电影实现方法的断言。部分可见变化也可能来自深度、遮挡和投影，设计仍需保留这些空间因素。

## 3. 当前实现的问题与原因

### 3.1 几何上有断点，时间上却一直存在

`entity-model.ts` 已把轨道切成多个弧段，不能判断为完全没有分段。当前有效外围主要是 `group === 11` 的子午方向轨道：八个方向，每条有三条相邻细轨，各细轨再生成六段。`group === 10` 的纬向壳层虽然仍有生成代码，但被最终返回前的过滤移除，不能直接重新启用它来增加效果。

这些弧段几乎同时常驻，缺口较规则；多条邻近轨道和多个平面叠加后，观看者会自动补全成稳定环架。继续增加断点数量，可能只会形成更多细碎的虚线环。

### 3.2 运动主要属于整个组

`entity-scene.ts` 对 `motionGroups.get(11)` 设置连续旋转。单个外围弧段没有自己的出生时刻、持续时间、增长、追尾和休眠阶段。组级 `uAlpha` 主要用于聚焦淡化，不能表达各段错峰出现和消失。

`ribbon-material.ts` 已有局部端部渐隐、空间明暗和轻微能量起伏；这些是沿已有弧段的材质变化，并没有改变弧段的生命周期。只增强这部分脉动，仍然会保留常驻环架。

### 3.3 流光和结构主体没有共同的可见窗口

现有 `EntityFlow` 沿闭合母路径移动，`coverage` 依据静态弧段采样。把静态弧段隐藏后，如果继续使用这份覆盖和常驻横档，可能留下悬空亮点、刻度或暗环。动态窗口必须同时约束主轨、伴随细线、横档、附着电路和流光。

### 3.4 单帧截图不足以验收

某一帧出现缺口，不代表它会生长或消散；像素变化也可能只有相机旋转。本轮必须固定相机和根旋转，连续观察同一弧带的头尾，再检查正常旋转下的整体观感。

## 4. 方案比较与推荐

| 方案 | 能解决什么 | 主要代价或缺口 |
| --- | --- | --- |
| 为现有静态片段增加独立淡入淡出 | 改动较小，消除同时常亮 | 缺口和空间位置仍偏固定；只有闪现，难以表现增长和尾部追赶 |
| 不可见母轨道加固定容量的动态弧带池 | 同时控制位置、长度、生命周期和结构束；能复用当前 Ribbon 与动态尾迹更新方式 | 需要独立的时间采样模型、动态缓冲及统一附着规则 |
| 完整轨道几何加 GPU 时间窗口 | 可批量计算窗口，CPU 更新量少 | 整圈仍参与提交；绕接缝、细节附着和多窗口调度更复杂，程序化顶点还需适配现有雾坐标注入 |

推荐第二种。外围同时存在的弧带数量很少，先使用固定缓冲、CPU 按弧长采样和 Shader 柔边，比引入另一套 GPU 轨道变形系统更容易保证端点连续、与雾一致及可复现。推荐尚待用户评审，不表示已经确认实施。

## 5. 建模方式

### 5.1 母轨道只定义路径，不绘制底环

从现有有效外围轨道提取闭合路径、弧长度量、轨道平面、径向与侧向方向。优先保留现有半径约 10.9 的空间位置和倾斜层次；不重新启用已经被过滤的整层纬线。

完整路径只供采样和边界计算，不创建可见的完整 Mesh 或暗色底环。外围出现空档时应真正露出内部雾和网络，不能留下常驻的细圆、刻度圈或伴随线。

现有八个子午方向中，`k` 与 `k+4` 描述同一个完整大圆，只是参数方向不同，实际只有四条不同母轨道。第一版按 `{0,4}`、`{1,5}`、`{2,6}`、`{3,7}` 合并去重，各保留一份规范路径并绑定一个槽位，前进方向交给事件参数控制。不为相反方向再生成一条“新轨道”。同一时刻每个物理平面最多一段，因此不会因不同 ID 重复占据同一轨道而拼满整圈。

若后续调整平面，必须依据路径或平面法线的几何等价性去重，不能只比较 ID；当前四条轨道的姿态保留，不逐事件随机改变平面来制造跳动。

### 5.2 弧带事件与固定槽位

建议用四个固定槽位，每槽位最多一个活动事件。事件至少记录轨道 ID、事件序号、种子、出生时间、持续时间、初始路径进度、方向、速度、峰值长度和强度。种子只决定一次事件的参数，不在逐帧采样时调用 `Math.random()`。

槽位的数组、几何与材质在初始化时分配，事件替换只重写数据。结束后槽位进入休眠，活动顶点 alpha 归零；不能沿用上一事件的尾迹。一个事件包含整束结构，不为每条细线分别随机调度。

### 5.3 一段弧带由相互关联的细节组成

建议一条较清晰的暖金主轨，加两条较弱的平行伴随线，局部带少量横档与短折线。细节共享同一事件进度和生命周期，允许小幅长度或亮度差异，不能形成三条各自闪烁的线。

横档和电路以母轨道弧长为锚点，只有锚点进入当前可见区间时才绘制，并乘该位置的头尾包络。事件死亡后全部消失。不要把一套完整刻度环留在动态主轨下面。

## 6. 生命周期与运动

### 6.1 时间轴

一次事件分为出现、生长、推进、收尾、休眠。推荐归一化年龄 `u` 的初始划分：

| 阶段 | 年龄范围 | 可见行为 |
| --- | --- | --- |
| 出现与生长 | 0–0.25 | 从短段柔和显现，头部前进，可见长度逐渐增加 |
| 推进 | 0.25–0.65 | 保持局部弧长，整体沿母轨道移动，亮度有克制的局部差异 |
| 收尾与消散 | 0.65–1 | 尾部更快追向头部，长度收短，整束逐渐淡出 |
| 休眠 | 本次事件结束至下次出生 | 不渲染该束任何底线、横档或流光 |

所有阶段使用连续平滑函数连接，开始和结束的 alpha 为零。空间端部渐隐与时间渐隐是两个独立因子，最终透明度还要乘聚焦权重、深度权重和既有体积透射；不要互相覆盖。

### 6.2 头尾关系

头部按母路径的归一化弧长推进：`head = start + direction × speed × ageSeconds`。长度 `length(u)` 在出生时由零增长到峰值，收尾时降回零；尾部为 `tail = head - direction × length(u)`。速度与长度均使用“整圈比例”单位，避免把弧度、角度与弧长比例混用。

每帧只在头尾之间采样可见 Ribbon。正反方向均采用局部进度 0 到 1 生成几何；先以不回绕的连续路径进度计算头尾、附着和纹理，再只对位置查询执行 modulo。跨过 0/1 接缝时不能连接成穿过球心的直线，也不能让尾迹突然清空。相邻采样点和 Ribbon 的 previous/next 位置必须属于同一连续弧段。

外围推进主要来自弧带窗口移动。替换掉 `group 11` 原有持续旋转和旧外围常驻几何，保留外层根节点的正常用户拖动、全局旋转和呼吸。旧模型中已烘焙的轨道姿态只应用一次，不能再叠加同一套组级 Euler 动画。核心组 0、1、2 的运动不由这项替换控制。

### 6.3 错峰且可复现的调度

推荐按槽位使用固定周期与不同相位，周期和相位由种子确定；每个周期内部再确定本次事件的出生偏移、寿命、起点、长度及方向，轨道仍绑定该槽位。生命周期必须短于周期，留出明确休眠。按 `floor((motionTime + phase) / period)` 推导事件序号，再由“全局种子、槽位 ID、事件序号”派生参数。

这种按绝对动画时间采样的方式，保证相同种子和时间得到同一结果，不受 30/60/120Hz、掉帧或采样顺序影响；测试与截图可直接跳转指定时间，无需补跑历史事件。槽位只在事件切换时更新元数据，逐帧只计算连续状态。

不要让所有槽位在页面打开时同时出生。相位直接采样一个已错开的稳定状态，避免首屏只有空白或者四段同时爆亮。有限周期不代表每次完全重复：不同事件序号会改变起点、方向、形态和寿命。

## 7. 建议调试参数和约束

以下均为第一版起点，最终以固定镜头的连续画面为准。

| 参数 | 初始建议 | 必须保持的约束 |
| --- | --- | --- |
| 活动弧带槽位 | 4 个 | 活动事件总数不超过 4，同一母轨道最多 1 个 |
| 母轨道 | 八个方向合并为 4 条唯一大圆，每槽绑定 1 条 | 按物理轨道去重，不能把反向参数视为两条轨道 |
| 单段峰值长度 | 一圈的 0.12–0.30 | 包括伴随线在内不超过 0.35 圈；保留大缺口 |
| 每次持续时间 | 2.4–4.0 秒 | 有明显增长和追尾，不只改变整体亮度 |
| 每槽周期 | 6.5–8.5 秒 | 出生偏移加寿命小于周期；休眠至少 1 秒 |
| 周期内出生偏移 | 0–0.6 秒 | 不跨周期重叠，切换事件时状态为零 |
| 路径速度 | 每秒 0.07–0.16 圈 | 同事件连续，方向不逐帧反转 |
| 每束组成 | 主轨加 2 条伴随线 | 伴随线更暗，不能填满主轨的缺口 |
| 每线采样 | 32–48 个线段 | 近景无明显折角，成本有固定上限 |

每条轨道单段长度受限，是模型可验证的底线；不同平面在投影中仍可能拼成环，因此还要看连续画面。若外轮廓仍接近封闭圈，先降低同时活动数量、缩短弧长或拉开平面，不通过随机闪烁、加粗或增加 Bloom 掩盖。

若节奏过空，优先延长已有弧带的推进阶段、调整槽位相位，再考虑增加数量；不要求任何一帧都达到四段。暖金底光和局部暖白高光沿用已有光感，不让整条弧带持续纯白。

## 8. 渲染实现和既有系统衔接

### 8.1 固定动态缓冲

复用现有动态尾迹的思路，初始化固定大小的 position、previous、next、alpha 与进度属性，更新数组并标记需要上传；不每帧创建 `BufferGeometry`、`Material` 或 `Vector3` 数组。主轨与伴随线按相同用途合批，横档和电路另用一个受控批次，不按事件创建独立 Mesh。

Three.js 的 [BufferAttribute](https://threejs.org/docs/pages/BufferAttribute.html) 支持自定义属性、动态使用方式及修改后上传；沿用项目已有的更新方式即可。柔边、头尾包络和颜色继续由 [ShaderMaterial](https://threejs.org/docs/pages/ShaderMaterial.html) 承担，不需要新渲染引擎或依赖。

建议新增独立的外围动态几何更新器，复用 `ribbon.ts` 的路径度量和采样，避免将 `createRibbonGeometry()` 直接放进每帧循环。静态核心轨道与现有其他流光继续使用原路径。

### 8.2 与体积雾一致

`volume-material.ts` 会遍历 Mesh、LineSegments 等对象，注入基于 `position` 的视空间坐标，并在颜色输出前乘透射。本方案通过 CPU 更新真实顶点位置，保持该坐标链路有效；若改成顶点 Shader 里计算位置，必须另行修改注入点，不能仍使用占位顶点计算雾。

动态缓冲对象和材质在现有 `NeuralVolume.attachRoot()` 遍历之前创建并加入 root，整个页面生命周期复用。这样标准档、低档、关闭再开启都能得到同一套透射与恢复行为，不需要每个事件重新挂载材质。新 Shader 保留既有输出 include 和材质补丁链，雾发光仍只合成一次。

### 8.3 外围流光一并收敛

移除被替换外围的旧静态 coverage 与旧闭合 flow 渲染路径。第一版直接由弧带的移动头部及短亮尾表达能量推进，不再额外叠一套绕完整外环跑动的亮点。核心和纤维的 flow 保留。

若后续确需外围额外流光，必须挂在活动事件内，受同一可见窗口、生命周期和附着条件约束；不得仅根据旧闭合母路径的 coverage 判断可见性。

### 8.4 相机与空间边界

默认拟合边界按所有候选母轨道的完整运动包络计算，包含伴随线偏移、呼吸及既有屏幕宽度留白。不能每帧根据当前活动弧段重新缩放相机，否则弧段消失会导致主体大小跳动。

新装饰继续不参与记忆拾取、关系计数或语义布局。分类与单节点聚焦沿用既有装饰淡化，直接关系节点与边不因装饰生命周期而消失。

### 8.5 Shader 错误归属

当前 `scene.ts` 的 renderer 级 `onShaderError` 会对任何程序编译错误关闭体积雾。接入动态外围层时必须调整该路由，不能新增另一个覆盖全局回调的处理器。

外围层使用独立材质，不能与核心共用同一材质实例；在其 `defines` 中加入唯一的层标记，例如 `FLYENV_OUTER_ARC_LAYER=1`，并保留原 `customProgramCacheKey` 和雾补丁链。该标记进入实际 Shader 源码并形成独立程序变体，不能仅依靠对象名判断编译程序的归属。

唯一的全局错误入口通过回调提供的 `gl` 和 Shader 句柄读取 Shader 源码，检查该标记：明确属于外围程序时记录日志、标记该层失败，并在下一帧更新前关闭外围对象与缓冲写入；不把该错误直接路由为全局关雾。不在编译回调内销毁正在使用的 GPU 资源，也不因下一个事件出生而自动重启失败层。

未带外围标记的错误继续交给既有全局降级处理。标记只说明故障程序属于哪一层，不证明根因一定在外围代码；若共享雾代码也使核心或体积 pass 编译失败，该未标记错误仍会触发既有雾降级。不能用外围隔离吞掉这些后续错误。新增故障通知跟随页面生命周期释放，不增加循环或重试。

## 9. 时间、所有权和失败边界

状态与资源仍由页面内的 `NeuralScene` 和 `NeuralEntity` 持有。纯时间模型负责“给定种子和时间生成状态”，渲染对象负责写缓冲、更新材质和销毁。没有跨页面任务、IPC、服务生命周期、持久化或新 Pinia 状态，也没有模块边界例外。

- 减少动态：冻结进入该模式时的 `motionTime`，保留当时的弧带位置、长度和明暗，不让所有事件重置到出生状态。UI 聚焦命令仍可更新可见权重。恢复后从该时间继续，不能追赶真实墙钟。
- 页面隐藏：沿用现有暂停入口；返回时不把后台时长计入动画，避免集中换代或闪烁。不新增独立 RAF、interval 或 timeout。
- 重置视图：复用既有场景和动画时钟，只恢复相机与聚焦，不销毁弧带池、不重新抽种子。减少动态下重置也保持冻结形态。
- 重复聚焦：最新目标替换旧目标，材质权重与事件状态分离，不重建几何。
- 销毁：移除新增对象并释放自有 geometry/material，遵守体积材质补丁的既有恢复次序；共享资源只释放一次。
- 候选轨道无效：逐条过滤并记录原因；有效候选继续工作。某槽位无有效候选则隐藏该槽位，不阻断其他槽位和记忆网络。
- 新外围层初始化或 Shader 失败：失败限定在外围装饰层，明确报告诊断并关闭该层；不得自动恢复旧的完整环架、重建整个场景或重放用户选择。GPU 适配错误必须修复，关闭只作为运行降级。
- 截图或录屏失败：只影响证据保存，不重建场景，也不撤销已完成的实现。

## 10. 文件分工与实施顺序

| 位置 | 拟承担的修改 |
| --- | --- |
| `entity-model.ts` | 将当前有效外围静态弧段拆为母轨道定义；保留核心与业务模型；更新完整候选包络 |
| 新 `outer-arc-model.ts` | 事件参数、确定性调度、头尾/长度/alpha 采样与约束，保持无 DOM、无 Three.js 资源 |
| 新 `outer-arc-layer.ts` | 固定动态缓冲与结构束更新，复用路径采样及 Ribbon 属性约定 |
| `entity-scene.ts` | 接入动态层，移除对应旧外围几何、常驻附着物和 flow；统一时间、聚焦、雾绑定与释放 |
| `ribbon-material.ts` | 必要时增加独立用途参数，表达动态空间包络；不得破坏静态核心或既有 flow |
| `scene.ts`、`main.ts` | 将现有全局 Shader 错误入口增加外围程序归属路由，沿用雾降级；必要时补齐暂停、减少动态或边界传递，不增加面向用户的调参面板 |

方案实施后再记录最终参数和证据；本次不将设计稿状态写成已完成实现，也不创建提交或推送。

## 11. 验收标准

### 11.1 行为回归

使用有代表性的种子及密集时间采样，验证：

1. 相同种子和时间结果一致，采样顺序、帧率及直接跳时不改变结果；不同事件能形成变化。
2. 出生、阶段切换、死亡、周期切换时位置/alpha/长度连续，无越界或 NaN；休眠时整束完全不可见。
3. 正反方向跨 0/1 接缝时不跳变、不穿心，不错误拉出长直线。
4. 反向参数重复的大圆先被合并；按物理轨道最多一个活动事件，总数不超过容量；包含伴随线在内的可见弧长不超过上限。
5. 横档、电路与流光不越出事件窗口，事件死亡后没有残留；核心及纤维层不被外围替换误删。
6. 减少动态和隐藏暂停保持形态，恢复不追赶墙钟；聚焦、重置不重抽种子或扩大可见数量。
7. 反复切雾档位、聚焦和挂载卸载后无重复材质补丁及资源增长。
8. 用受控的外围 Shader 编译错误验证只关闭外围层，核心和雾继续工作；再用未标记的共享雾程序错误验证原雾降级仍触发。关闭检查故障注入后，正常加载不能残留标记外的错误或失效状态。

### 11.2 必须查看连续画面

交付两段至少 20 秒的连续画面：一段固定相机和根旋转，另一段正常全局旋转；都保留局部弧带动画。固定画面里应能跟踪同一弧带从出现、伸长、推进到收短消散，不能只有整环转动或闪烁。

另外保存同一事件的出生、生长中、峰值、收尾、休眠五个阶段，以及全局、分类和单节点画面。检查普通正面、侧面及中间角度；在 1440×900、1280×800 和一组窄屏内容区查看，DPR 1/2 均检查。

通过标准：外围存在较大的真实空档，各束错峰变化，主体仍完整可读；没有稳定经纬网外壳、同步闪亮、硬切端点、离轨细节或纯白大光管。雾应从缺口中自然显露，关闭雾后弧带生命周期仍成立。各类记忆、直接跨类关系、拾取和返回不受影响。

### 11.3 成本检查

固定容量分配是硬约束，不能用逐帧 new 几何或每条线独立 draw call 换取效果。四槽、三线、每线 48 段的 Ribbon 约为 3456 个三角形顶点，附着细节另设固定上限；计算总量时不要把旧外围和新外围重复保留。

在同设备、同视口/DPR、同雾档位记录改动前后至少 20 秒的帧耗时中位数、P95、draw calls 和 renderer 资源计数。若中位数或 P95 变差超过约 10%，先减少采样、横档或次要伴随细节并复测。该阈值是调试警戒线，不是当前已测结果；通过模型测试或保持顶点预算也不能直接宣称帧率达标。

最终交付包括实际录屏、定帧对照、采用参数、回归结果和性能记录。人工连续观看是独立验收项，不能由静态截图或测试通过替代。
