# MySQL Cluster 插件设计

日期：2026-10-20  
状态：用户已审阅认可本设计并要求继续；实施计划待审阅，尚未进入业务实现。

## 1. 目标与已确认范围

新增独立插件 `plugins/mysql-cluster`，模块 ID 与 typeFlag 均为
`mysql-cluster`，显示名称为 MySQL Cluster。保留现有内置 MySQL 模块。

用户要求三个 Tab：

1. **MySQL 实例**：创建多个实例，选择已安装 MySQL 版本、端口、Socket 等；
   列表显示版本号、版本路径、端口、Socket、运行状态；支持启动、停止、重启，
   通用列表下拉菜单包含编辑、配置文件编辑、日志查看、数据管理、删除。
2. **服务**：显示当前已安装 MySQL 版本，沿用当前服务列表体验，移除启动、停止、
   重启等实例运行操作。
3. **版本**：沿用当前 MySQL 版本管理，可安装版本。

用户进一步认可一键建立主从复制和 Group Replication。首版创建模式为独立实例、
主从复制、Group Replication；后两种模式创建并管理一组本机实例。
实例页负责组的展示和操作，不增加第四个 Tab。

成功标准：同一套 MySQL 二进制能够同时运行多个隔离实例；选择模式和版本后，
通过一次创建操作完成空实例初始化、配置、启动、复制建立及健康验证；
状态来自真实进程及数据库查询，失败不显示为完成。

## 2. 范围与版本策略

- 三种模式均操作本机原生 MySQL，覆盖 macOS、Windows、Linux 的代码路径，
  各平台实际验收结果分别记录。
- 独立实例复用宿主已安装版本作为候选；启动前检查真实 mysqld、初始化方式及必要工具。
  不兼容项展示明确原因，不仅凭下拉列表中的版本文字认定可用。
- 首版一键复制路径面向 MySQL 8.0 与 8.4；同组所有节点选择完全相同的安装版本。
  针对 8.0.23 前后的复制语法差异进行版本分支和能力检查；Group Replication
  必须检查实际插件存在及相关变量，具体不满足条件的构建不可创建。
- 优先以 MySQL 8.4 完成原生联调；其他版本只有实际支持或验证的功能才能启用，
  未验证结果不得写成已验证。
- 主从默认一主一从，可调整从节点数量；Group Replication 默认三节点单主，
  首版组节点数限制为 3、5、7、9，便于表达多数派与容错能力。
- 首版一键建立只接纳插件新建的空节点。已有业务数据的独立实例保持独立，
  不自动转换、克隆、覆盖或加入复制组；界面说明该限制。
- 首版不含远程主机、混合版本组、半同步、多主 GR、自动主从故障切换、
  已有数据库迁移及 MySQL Shell/Router 下载管理。
- MySQL Router 是后续独立增强项；首版提供各节点真实连接信息，
  不宣称 GR 自动选主等同于客户端连接自动切换。

## 3. 界面和交互

### 3.1 MySQL 实例 Tab

列表按组展示：独立实例直接作为一行，复制组有组标题及成员行。组标题显示名称、
模式、健康摘要；成员行显示名称/ID、版本号、版本路径、TCP 端口、Socket/命名管道、
数据目录、角色、运行状态、复制状态、延迟和最近错误。
长路径使用现有溢出提示与打开目录交互，窄窗允许表格横向滚动。

创建入口打开表单：名称、模式、已安装版本、节点数量/从节点数量、起始 TCP 端口、
数据根目录、管理员密码；独立实例可直接指定数据目录和 Socket。
组模式展开各节点预览，允许分别编辑端口、Socket 与数据目录。
GR 使用 XCom 通信栈，单独分配并展示组通信端口。MySQL X Protocol
默认关闭，避免多个实例竞争默认 X 端口；未来启用时必须独立分配端口。
所有输入、下拉框和数字控件占满所属表单列。

自动分配是预填建议。提交前检查 TCP/GR 端口交叉重复与占用、Socket/管道重复、
规范化后的目录重叠、数据目录非空、可写性、版本文件可用性及剩余节点配置。
端口预检和真正 bind 之间仍可能产生竞争，启动时的实际冲突必须如实报告。
Unix Socket 校验平台路径长度；Windows 展示实际命名管道语义，不将 Unix 路径
当成 Windows Socket 路径。

每行提供启动、停止、重启和现有 `host-list-poper`/`host-list-menu` 风格的更多菜单：
编辑、配置文件编辑、错误日志、慢日志、数据管理、复制连接信息、删除。
组提供启动、停止、重启、刷新状态；首版不提供成员在线扩缩容。

运行中实例禁止直接修改版本、端口、Socket、目录等身份字段。
复制组成员的版本与拓扑关键项只能在停止整个组后通过组编辑流程修改；
更换已有数据目录对应的 MySQL 版本还必须通过兼容性校验，不能盲目升级或降级。
首版不支持已有数据实例的跨版本切换，允许名称/备注编辑。

删除先弹现有确认框，再确认目标进程已经停止；停止失败则不移除记录。
默认删除管理记录及插件生成的非数据配置，保留数据目录并返回位置；
不提供隐式递归删除业务数据。复制成员不能单独删除，需删除其所在组，
避免留下一套无法表达的拓扑。

### 3.2 服务与版本 Tab

服务候选来自 `BrewStore().module('mysql').installed`，版本安装使用现有
`VersionManager` 的 `type-flag="mysql"`。安装完成、切换至服务或创建实例时刷新候选。
两页共用内置 MySQL 的安装来源，不复制下载目录或在线版本目录。

服务页保留版本、安装路径、备注、环境变量/别名、自定义版本目录和刷新能力；
隐藏所有启动、停止、重启以及会打开内置默认实例的数据管理入口。
优先以插件本地视图复用现有列表逻辑；如果必须扩展宿主组件，只允许默认值保持
现有行为的通用展示接口，不能引入 MySQL Cluster 专有属性。
版本被实例引用时展示使用者；卸载安装版本必须阻止破坏插件已知运行实例，
不能为了卸载普通版本而自动终止其他实例。
其他宿主入口移除二进制导致的外部变化通过下次检查展示“版本不可用”，不删除实例。

### 3.3 数据管理

沿用 `src/render/components/Mysql/Manage/` 的交互能力：数据库和关联用户列表、
创建数据库/用户、密码管理、备注、备份目录选择及数据库备份。
需要插件本地适配连接定位和状态，不直接使用原来的 `bin` 索引与按版本号查配置方式。
所有缓存、凭据、备注、备份目录和操作锁按实例 ID 隔离。

连接固定使用该实例已验证的本地端口/Socket；失败不得回退至默认 3306 或其他节点。
创建数据库、用户及修改密码属于写操作：组内仅允许当前可写主节点执行，
主节点不可确认或非 ONLINE 时禁止写入，展示原因；只读成员可以查看和备份。
不得通过关闭只读模式完成一个管理操作。刷新角色后再决定是否可写。
GR 用户/密码变化对组的影响应在操作说明中表达，不能伪装成仅影响一个物理节点。

## 4. 文件结构和责任

- `plugins/mysql-cluster/plugin.json`：独立插件注册，初始版本 `0.1.0`。
- `shared.ts`、`policy.ts`：实例/组/操作结果结构、输入校验与兼容规则，无进程全局状态。
- `render/Module.ts`、`aside.vue`、`Index.vue`：模块注册、扩展参数注册、三个 Tab 容器。
- `render/controller.ts`、`manager.ts`：模块单例、Storage 适配、操作完整生命周期。
- `render/Instances.vue`、`InstanceDialog.vue`、`InstanceActions.vue`：实例列表、表单、菜单。
- `render/Services.vue`：已安装 MySQL 列表展示。
- `render/Config.vue`、`Logs.vue`、`manage/`：实例配置、日志与数据管理界面和适配。
- `fork/index.ts`：Base 生命周期与插件 IPC 入口，不承担全部业务实现。
- `fork/catalog.ts`：插件实例清单、磁盘运行元信息和真实实例发现。
- `fork/runtime.ts`：初始化、mysqld 进程、就绪检测、精确停止与 PID 恢复。
- `fork/config.ts`：配置生成、解析、实例身份字段及版本分支。
- `fork/replication.ts`、`fork/groupReplication.ts`：主从和 GR 编排及健康检查。
- `fork/manage.ts`：固定实例目标的数据库管理和备份。
- `lang/en.ts`、`lang/zh.ts`、`lang/index.ts`：插件独立双语，其他语言回退英文。
- `tests/`、`README.md`：聚焦回归与平台验收说明。

实现中允许按实际文件大小继续拆分；不能将插件领域字段泄漏进公共服务类型或 BrewStore。

## 5. 状态、持久化和生命周期

### 5.1 状态归属

- 表单、筛选、选择、弹窗可见性属于挂载的 Vue 组件。
- 插件领域状态由模块本地类单例管理，通过 `reactiveBind` 暴露；不新增 Pinia。
- 使用 `StorageGetAsync`/`StorageSetAsync`，独立版本化 key
  `flyenv-plugin-mysql-cluster-v1`；不写 `config.setup`。
- Fork 持有进程、PID、端口、身份校验、实际数据库状态与磁盘运行清单。
  Fork 运行清单是已准备实例的进程定位记录，不替代 renderer 的插件偏好存储。
- 配置、日志、PID、运行清单位于插件专属数据目录，各实例用不可变 ID 分隔；
  与内置 MySQL 的 `my-<version>.cnf`、`group/group.json` 等互不混用。
- 管理密码和保存的数据库密码按实例隔离，延续现有数据管理的明确保存交互；
  不在表格、日志、通知、普通操作快照及子进程命令行中暴露密码。

配置保存成功后才发布领域状态。初始化或创建过程中已经发生的磁盘副作用单独记录，
保存失败时保留可恢复的实例，不能删除数据或重新初始化。

### 5.2 通用服务生命周期

每个实例使用独立 `ModuleInstalledItem`，插件模块设置 `isOnlyRunOne = false`。
通过 `startExtParam`/`stopExtParam` 携带实例 ID 与不可变配置快照，复用公共
`start()`、`stop()`、`restart()`；组编排只能组合这些方法，不另写 renderer 启停 IPC。
插件安装版本候选与运行实例列表分开，不能让普通 mysql 模块的独占版本切换停止组成员。

Fork 为每个实例维护独立 PID 文件和配置身份；复用 Base 的停止快照、
精确配置参数筛选及信号/退出确认策略。不能使用模块级单一 `appPidFile` 覆盖所有节点，
也不能仅按公共 mysqld 可执行路径定位停止目标。
服务启动登记返回实例配置身份、真实 PID 和可重放的精确停止参数，
宿主退出/插件禁用仍可回收所有已登记实例。
插件 `stopService` 参数顺序遵守插件约定，不能照搬内置模块插入 ServiceStopContext
的特殊签名。

冷启动和页面重新进入从 Fork 重新发现运行状态；存储里的布尔值不作运行依据。
未知/身份不符的进程不能被直接停止，实例显示未知或冲突原因。

## 6. 一键创建与复制流程

### 6.1 所有模式的共同流程

1. Controller 捕获不可变创建请求并占用组/实例操作锁。
2. Fork 校验完整组配置、真实二进制及工具、目录和端口，生成待创建清单。
3. 保存待创建记录后逐个准备插件独占目录与配置，初始化空数据目录。
4. 初始化凭据通过驱动连接/标准输入等受控通道处理；进程使用 argv 数组，
   不拼接含密码、路径或用户输入的 shell 命令。
5. 使用公共生命周期启动节点，确认精确 PID、端口和 SQL 就绪。
6. 独立模式结束；组模式执行其复制流程。
7. 查询并验证实际拓扑，持久化完成阶段后才显示完成。

初始化前后的状态分为未开始、初始化中、已初始化、结果未知，写入运行清单。
已有数据库/部分初始化痕迹不能进入自动重新初始化；显式重试检查已完成阶段。
创建不会复用任意非空目录。

### 6.2 主从复制

分配唯一 `server_id`/server UUID，启用 GTID、Binlog、ROW 及副本必要配置。
初始化管理账号等节点本地准备不能生成互相冲突的事务历史。
自动生成最小权限复制账号，配置 GTID 自动定位通道并启动复制，
将从节点置为只读，防止普通管理操作误写。
验证接收线程、应用线程、最近错误、源节点身份和复制进度。
复制延迟未知时显示未知，不能把 NULL 当作 0。

组启动顺序为源节点就绪、从节点启动、通道恢复、健康验证；
源节点失败则不继续建立依赖它的新通道，已成功启动的节点保留事实状态。
源节点故障不自动提升从节点，避免普通异步复制产生未授权的数据分叉。

### 6.3 Group Replication

能力检查覆盖 GR 插件、GTID、ROW、唯一身份、InnoDB 与表主键要求。
首版固定单主模式和 XCom，SQL 端口与组通信端口独立分配。
创建同组 UUID、种子列表和恢复账号，完成配置后只在选定首节点临时 bootstrap。
无论首节点启动成功还是失败，都必须执行 bootstrap 关闭处理；
关闭失败则明确阻断后续引导并保留错误，不把所有节点设为 bootstrap。

其余空节点通过分布式增量恢复加入，等待真实 ONLINE 和唯一 PRIMARY。
保留同组事务来源，不能执行 RESET GTID/任意事务注入来强行绕过冲突。
新建组不能验证成功时报告各节点实际状态。
单节点故障后的选主交给 GR；页面展示最新主节点并据此限制写管理操作。

整个组关闭后的启动必须区分正常成员重连和完整集群恢复。
全停恢复读取各成员真实 GTID/恢复状态并选择足够新的节点，不能固定以第一行
重新 bootstrap；无法确定安全恢复节点时停止自动恢复并报告原因。
不得强制忽略失联成员、修改多数派或通过强制成员列表掩盖网络分区。

## 7. 操作契约

全部长操作由 singleton controller 持有，页面卸载不取消，页面回来绑定原进度。
Fork 内同时持有按实例/组的真实操作互斥，防止来自不同入口的并发执行。

| 操作 | Owner / lifetime | 中间事件 | 成功/失败终态 | 重入及服务交互 |
| --- | --- | --- | --- | --- |
| 加载/发现 | Controller + Fork catalog；请求开始到完整快照 | 扫描进度可选 | 完整快照或读取失败 | 同请求合并；读取失败不覆盖已有列表 |
| 创建/初始化 | Controller + Fork runtime；跨页面直到创建终态 | 校验、准备、初始化、启动、复制、验证 | 所有必要节点验证通过；或带逐节点结果的失败/部分完成 | 同组同请求共享 Promise；冲突编辑拒绝；已有数据不重建 |
| 实例启停重启 | ModuleInstalledItem + Fork runtime；从前置校验到真实 PID/退出确认 | 宿主 progress / code 200 均非终态 | 公共 terminal success/error | 同动作合并，相反动作等待或明确拒绝；失败保留实际运行事实 |
| 组操作/恢复 | Controller；成员生命周期及 SQL 健康检查结束 | 逐成员阶段与恢复状态 | 逐成员结果聚合，允许部分完成 | 不重复执行已完成成员；GR bootstrap 受独立组锁保护 |
| 配置读写 | Controller + Fork config；文件读写及验证结束 | 校验/保存 | 原子写成功或明确失败 | 按实例串行；关键身份项受管理配置约束；保存不隐式重启 |
| 数据管理/密码/备份 | Controller + Fork manage；连接/子进程到关闭 | 查询/导出进度 | 主操作结果，备份逐库结果 | 按实例及操作类别互斥；组写操作必须确认主节点；取消选择不等于失败 |
| 删除 | Controller + Fork runtime/catalog；停止及记录保存完成 | 停止、删除记录 | 停止确认且管理记录删除成功；否则失败/部分完成 | 与该实例/组其他变更互斥；保留业务数据 |
| 安装版本 | 现有宿主 VersionManager | 现有安装进度 | 现有安装终态 | 完全复用宿主生命周期，完成后刷新候选 |

每个操作保存请求快照、阶段、节点结果和最近错误；只有声明的终态清除监听和 busy。
通知/日志/目录打开失败属于附加结果，不覆盖已成功保存、启动或备份的主结果。
SQL 连接和文件/子进程资源在所属操作终态释放；页面不拥有这些清理逻辑。

## 8. 失败边界和恢复

- 版本、权限、目录身份和完整组配置是前置必要依赖，失败不执行初始化。
- 单个节点初始化/启动是该节点后续复制步骤的必要依赖，不授权删除其他节点的数据。
- 依赖主节点的步骤等待主节点；其他独立节点的停止/状态查询逐项收集结果。
- 写配置、初始化、复制配置、启动、停止的完成事实分别保存，后续通知/刷新失败
  不能使其被错误重放。
- 必要停止失败、SQL 建链失败、复制线程异常、GR 非 ONLINE 都必须传播。
- 非法 PID 候选逐项跳过并说明原因；共享进程快照不可用时不执行任何依赖它的停止。
- 页面同时显示完成、失败、跳过和未知；组部分完成不显示整个组健康。
- 重试先按 Fork 真实状态判断已完成步骤，不重复初始化，不默认清目录、不更改现存密码。
- 配置编辑不能偷偷改掉实例端口、Socket、datadir、pid-file、server_id 或复制拓扑，
  保存时核对受管理键；日志与备份目标也必须局限于用户明确选择的实例/目录。

## 9. 验证与交付

实现计划应把以下检查绑定到对应功能任务，而非最后一次性补测：

1. 配置与校验：同版本多实例、端口交叉占用、Socket/命名管道、路径重叠、空白/符号路径、
   X 端口禁用、缺少二进制/插件、不兼容语法、非空/部分初始化数据目录。
2. 生命周期：重复调用、中间进度保留、终态清理、页面重入、停止失败后禁止重启下一阶段、
   同二进制多个实例精确停止、重启应用恢复身份及宿主退出回收。
3. 创建与持久化：保存失败、节点初始化失败、成功后刷新失败、重试不重放副作用、
   一节点失败保留其他节点结果。
4. 主从：真实写入源节点后从节点追上、复制线程错误、延迟未知、只读写入阻止、
   不回退默认端口或其他实例、版本语法分支。
5. GR：仅一次 bootstrap 且终态必关闭、三节点 ONLINE/唯一 PRIMARY、节点退出后选主、
   全停后安全恢复、GTID 分叉/无法确认恢复节点时拒绝强制引导。
6. 数据管理：同版本实例的密码/缓存/备注/备份相互隔离，SQL 输入安全，
   非主节点禁止写，备份逐库结果与日志附加失败隔离。
7. UI：三个 Tab、创建三模式、通用菜单、服务页无启停、版本安装后候选更新、
   深浅色及窄窗、中文/英文、表单宽度、只读角色提示。
8. 项目检查：renderer operation boundaries、插件契约、聚焦 lint/type diagnostics、
   插件构建及归档内容/SHA-256 一致性；只运行与改动相关的宿主检查。

交付插件源码和 `mysql-cluster-0.1.0.flyenv-plugin` 包，README 清楚区分
真实原生联调、适配器/错误注入回归及尚待验收的平台。
不自动发布、安装到用户实际配置或改动已有 MySQL 数据；需要原生端到端验收时使用
独立临时数据根和空实例，不启动、停止或修改用户现有服务。

## 10. 默认约束核对

- Persistence：独立 Storage；无 `config.setup` 扩展。
- Renderer state：模块本地单例 + `reactiveBind`；无新增 Pinia。
- Service lifecycle：公共 ModuleInstalledItem 生命周期 + 插件扩展参数。
- Module ownership：插件专有字段/策略/类型均留在插件目录。
- Exception authorization：无；现有 MySQL 旧实现不构成本插件的例外授权。
