## 2. 当前效果与剩余问题

新版已经解决了一部分方向性问题：大型彩色光球明显减弱，分类记忆向核心展开，装饰结构增加了轨道束和横档，电路碎片覆盖南北半球，流光可以沿完整路径运行。后续应在这个方向上精修。

### P1 默认全局构图裁切

**现象：** 点击重置后，外壳上下超出画面，并进入顶部与底部 HUD 区域，用户无法直接看到完整悬浮体。

**代码原因：** `scene.ts` 的 `calculateBounds()` 以业务节点包围盒中心作为目标，半径下限固定为 13.4；装饰结构没有参与统一边界计算。`calculateHomeDistance()` 按整个画布估算距离后再乘 `0.8`，进一步拉近镜头。画布全屏铺设，没有扣除 HUD 占用区域。球体拟合还应考虑透视切线，不能将平面半径的 `R / tan(半视场角)` 直接当成完整球体的保守拟合距离。

**影响：** 完整轮廓被破坏，密度和大小也难以在不同窗口中比较；单纯缩小几何会改变结构比例，不能解决布局原因。

### P2 主环架缺少厚度和材质层次

**现象：** 主环与背景电路大多表现为相近的细线。增加平行轨道后，精细程度提高，但主环架仍缺少承担整体视觉重量的发光带。

**代码原因：** `entity-scene.ts` 将环架和电路转换成 `LineSegments`，结构 Shader 主要控制颜色、透明度与深度。模型中的平行轨道数量增加，并不会自动产生可控的屏幕宽度、横截面亮芯和柔光边缘。

**影响：** 金色主体仍偏线框；继续增加同类细线，容易增加杂乱度而无法建立主次。

### P3 中层体积不够连续

**现象：** 核心周围较密，外层存在大片空区；部分短电路片段悬在空处，缺少与主结构的组织关系。

**代码原因：** 业务节点集中向核心收拢，装饰粒子主要采用径向随机分布，外壳仍由固定半径的经纬弧构成。缺少沿主环架、径向总线和分类通路组织的中层支撑细节。

**影响：** 近看有很多元素，远看仍容易分成中心团和外围弧线。

### P4 流光亮点与轨道脱节

**现象：** 一些亮点比承载它们的轨道更显眼，尾迹可辨认成一串离散圆点。

**代码原因：** 每条流动路径当前复制四个头部，每个头部使用五个点组成尾迹；结构和流光分别控制亮度。流光点具有较强高光，轨道经过透明度与深度衰减后则较暗。闭合流动路径还可能跨越静态弧段的缺口。

**影响：** 动感已经成立，但连续的能量结构感不足。增加头部数量会进一步强化散点感。

### P5 分类聚焦没有覆盖整类内容及全部图层

**现象：** “项目”分类聚焦后，光球和列表突出，但其他分类的连线仍穿过主体；当前分类的部分记忆也可能偏到画面边缘。

**代码原因：** `focus()` 仍以分类中枢位置为镜头目标，距离采用固定下限和全局半径比例。新版记忆位置沿中枢到中心展开，中枢已不能代表整类内容的中心。聚焦只更新了节点、粒子、光球和装饰实体的部分状态；`createEdges()` 生成的普通连线仍使用固定颜色与透明度。

**影响：** 全局与分类视图的视觉规则不统一。只调亮当前光球会继续放大中心偏离和连线干扰。

## 3. 路径比较与推荐

1. **继续只调透明度、曝光和 Bloom。** 改动少，但解决不了裁切、主结构宽度和分类包围范围问题；容易使亮点先过曝。
2. **保留场景与模型契约，局部升级镜头、主环架、密度和聚焦策略。** 可逐步对照效果，复用现有交互和批量渲染。推荐采用。
3. **重做为复杂体积渲染或更换图形引擎。** 成本、性能和拾取维护负担较高，目前没有证据表明必须更换现有技术。

以下是推荐路径的具体设计；数值为首次调试起点，不表示用户已经批准，也不是参考视频测量值。

## 4. 方案一 统一边界与可用视口

### 4.1 让几何所有者提供边界

`NeuralEntity` 暴露装饰主体的保守局部包围球或等价的只读边界。生成模型时计算一次，包含主环、外壳、中层连接和流动路径的中心线，另加世界空间的呼吸与漂移幅度。屏幕空间的带宽、节点光点和柔光不计入这个固定世界半径，统一通过视口内缩留白处理。

各运动组会独立旋转，不能只取某一帧的轴对齐包围盒。以各旋转组原点为中心、覆盖该组所有点的半径可以提供旋转不变的保守边界。最终合并业务节点边界和装饰边界；远处背景星点不参与主体拟合。

全局主体围绕共同原点组织，不再仅按偏心的业务节点包围盒定位整个装饰体。主环的带宽与柔光余量计入投影后的像素留白，背景 Bloom 光晕允许自然延伸。

### 4.2 把场景容器放入 HUD 之外的区域

推荐直接调整 `#neural-scene` 的布局范围，使 canvas 与标签覆盖层占据同一个可用矩形；全屏背景继续由现有 CSS 提供。这样相机、投影和拾取都使用同一容器，不引入另一套坐标变换。

可用区域根据 `.topbar`、`#category-rail`、`#inspector` 和 `.control-dock` 的实际可见边界确定。桌面模式预留左右栏区域；紧凑总览也保留稳定的右侧栏宽，避免展开详情时主体突然大幅横移。窄屏沿用分类栏顶部排列，将详情改为有高度上限的底部区域，重新计算剩余矩形。

首次建议在可用矩形四周保留至少 16 CSS px；实际内缩取这个最小值与主轨半宽、柔光半宽、节点最大屏幕半径加安全余量中的较大者，再在内缩区域内拟合。常驻标签在该区域内避让，边缘悬停卡片向内翻转，不把标签宽度错误地换算为固定世界半径。主体直径初始以占可用矩形较短边约 80%–88% 为调试目标。可用区域不足以同时容纳面板和场景时，先折叠次要 HUD，保留全局返回、分类切换和缩放入口；不把场景压成接近零面积。

### 4.3 统一拟合算法

设主体半径为 `R`，相机垂直半视场角为 `v`，场景容器宽高比为 `a`。先得到水平半视场角 `h = atan(tan(v) × a)`；再按对称像素内缩后剩余宽高占原容器的比例 `sx`、`sy`，得到有效角度 `he = atan(tan(h) × sx)`、`ve = atan(tan(v) × sy)`。保守拟合距离从 `R / sin(min(ve, he))` 起算，再乘大于 1 的留白系数。删除原来拉近镜头的 `× 0.8`，不要只改变宽高比而忽略内缩区域的绝对尺寸。

相机对准当前目标包围球中心。默认加载、重置、窗口变化和面板布局变化使用同一规则。用户主动放大后允许局部超出画面，重置必须恢复完整视图。

主流程通过 DOM `ResizeObserver` 感知尺寸和面板变化，合并到下一动画帧处理。全局和分类切换都以最新目标替换尚未结束的相机过渡，防止旧动画继续写入镜头。零尺寸或页面隐藏时暂缓拟合，不启动重复渲染循环。

## 5. 方案二 为主环架增加有层次的发光带

### 5.1 明确三种结构角色

- **主环架：** 三层核心环的主轨及少量外壳骨架，承担轮廓、厚度和主要高光。
- **伴随细轨：** 主轨两侧的平行线、横档和刻度，提供精密感。
- **背景结构：** 远层电路、细碎纤维和较暗的断续弧，提供体积信息。

这些角色使用明确元数据，不通过数组下标推断。语义关系继续独立渲染，不能因为视觉增强而增加关系数量。

### 5.2 只升级少量主轨

主轨采用可批量合并的屏幕空间带状几何。每个曲线采样段展开为窄带，Shader 控制横向亮芯和柔光衰减；保留曲线原有三维位置、分段和组运动。每个运动组共享几何与材质，不为每个弧段创建独立 Mesh。

第一版采用受控的斜接或斜角连接，断点使用短距离淡出。避免尖角处无限放大的连接，连续采样段共享端点以减少裂缝。后续只有在真实近景出现问题时再增加更复杂的连接形式。

首次建议：主轨亮芯约 1.4–2.4 CSS px，柔光范围约 4–7 CSS px；伴随细轨更细，背景保留当前细线。所有宽度统一以 CSS px 定义，在 Shader 中按 DPR 和实际渲染分辨率转换，保证不同屏幕下粗细一致。

主轨与细轨通过少量横档形成可读的结构束。软光只围绕主轨展开，不生成覆盖整个球面的发光面片，不添加实体球壳。

### 5.3 在修正镜头后重新标定深度

现有深度衰减使用固定的视空间距离 18–52。修正全局镜头后，整体距离增加，不能沿用固定阈值导致全部结构变暗。

改为根据主体中心的视空间深度和半径归一化：近表面为 0、远表面为 1，各图层再使用各自的衰减曲线。这样缩放、分类聚焦和窗口变化不会使整个主体无故熄灭。主轨远层可见但明显弱于近层；背景结构衰减更强。

主轨亮芯、外沿、粒子和流光分别控制亮度。先以当前 Bloom 设置建立结构层次，再做小幅调整。颜色统一通过 Three.js 的颜色转换入口传入，避免不同 Shader 混用不一致的颜色空间。

## 6. 方案三 沿现有结构补足中层密度

保留真实可拾取节点数量。新增细节全部属于不可拾取的装饰模型，不计入节点数、语义关系数或分类列表。

中层主要覆盖主体半径约 40%–85% 的区域，但按以下结构分配，而不是均匀撒点：

1. 在主要环架附近生成短平行片段、少量横档和错层电路，形成局部结构带。
2. 沿现有分类到核心的纤维生成稀疏短支路，连接中层与中心。
3. 在中层与外壳之间增加少量短径向连接，减少外壳悬空感。

装饰支路附着在端点所属的同一运动组，不跨两个独立旋转组硬连，否则旋转后会出现脱节。确有跨组效果需求时，使用现有所有者每帧更新端点，且只保留极少量；本轮默认不新增这种动态跨组连接。

所有几何使用既有确定性随机种子。先重新分配已有碎片的位置与尺寸，再补充数量；保留可读空隙。验收时既看正面也看旋转后的侧面，避免仅某个角度填满。

## 7. 方案四 让流光与轨道共同构成能量结构

保持完整路径采样和现有组运动机制。先降低头部存在感，再改善尾迹连续性：

- 核心主轨初始使用每路 1–2 个流光头，外壳通常 1 个；纤维只让少量路径同时有高亮流光。减少密度后再判断是否需要补充。
- 尾迹使用与主轨相同的带状几何策略，按路径长度展开，头部短亮、尾部连续渐隐。沿路径距离采样，避免不同采样间隔造成速度和尾迹长度突变。
- 头部亮芯不明显宽于主轨，尾迹通常覆盖路径长度约 2%–5%，不保留清晰的“圆点串”。
- 流光穿过静态弧段缺口时，允许保留一条更暗的连续导引轨，或让该区段的流光按缺口掩码淡出；本轮推荐后者，几何与流光共享弧段覆盖信息，避免凭空穿过长黑区。
- 主轨有稳定底光，流光经过时局部增强；使用同一条路径上的能量包络协调两者，避免分别调参导致头部很亮而轨道消失。

保留各层差速和进动。减少动态开启时停止旋转、呼吸、漂移和流动，保留静态结构。自动旋转按钮继续控制整体自动旋转，内部动态仍由减少动态开关统一控制；按钮提示应与此行为一致。

## 8. 方案五 统一分类聚焦和关系图层

### 8.1 使用整类节点的边界

预计算每个分类的相机目标集合：本类中枢、全部本类记忆，以及通过跨分类 semantic 边直接相连的对端记忆节点。使用这个集合的包围球中心作为目标，按当前可用矩形拟合距离，保证本类和这些直接关联对端同时可见。这个选择优先完整显示一跳关系，接受比只拟合本类稍远的镜头；不加入对端所属分类的其他记忆、其他中枢或装饰外壳，不递归扩展。分类标签和点的屏幕半径按 §4.2 处理，不使用固定的 `max(13, radius × 0.78)`。

模型局部中心必须经过 `root.matrixWorld` 转成世界坐标；旋转过程中保持一致。分类列表变为完整高度、详情切换、窗口变化时都重新拟合当前分类。

点击单条记忆继续显示详情和直接语义关系，双击或“聚焦当前节点”再进入单点近景。单点近景拟合目标节点和直接语义邻居的范围，设置合理最小距离；不为放大一个点而把直接关联全部裁掉。单点模式返回分类时恢复分类拟合，返回全局时恢复全局拟合。

### 8.2 所有图层使用同一聚焦状态

聚焦状态由现有 `NeuralScene` 持有并传给节点、关系边、语义脉冲、光球、标签和装饰层，不在 DOM 事件中逐个修改材质。边的两个端点分类、边类型和与所选节点的关系作为批量属性或等价索引提供。

全局模式保持目前暖金统一、分类色辅助识别的方向。分类模式采用以下规则：

- 当前分类节点恢复分类色；其他分类节点保持低亮度。
- 当前分类的 membership 和分类内部 semantic 边清晰显示。
- 只有与当前分类直接相连的跨分类 semantic 边保留弱提示，对端节点保留足够辨识度；不递归展开全部其他分类。
- 与当前分类无关的 membership、semantic 和 visual 边显著降低亮度，避免全网连线穿过主体。
- 装饰轨道、纤维和纯视觉脉冲一起退后，不冒充当前分类的真实关系。

单节点选中时，高亮该节点的直接语义关系；membership 可作为归属提示，visual 边不进入语义关系高亮或关联数量。列表中的模拟关联说明继续保留。

首次建议将无关边压到其全局亮度的约 5%–10%，直接跨分类语义边约为内部语义边的 25%–40%；最终以可读性确定。淡化同时覆盖颜色、透明度和脉冲，不能只改节点而保留全亮连线。

### 8.3 收敛标签

全局默认不强制显示八个完整标签框；优先保留悬停、选中或少量无遮挡标签，分类栏继续提供完整入口。分类聚焦时只突出当前分类及必要的直接关联提示。标签位置和拾取继续使用同一场景容器。

## 9. 文件分工和状态所有权

建议改动落点：

- `entity-model.ts`：装饰主体边界、主轨角色、中层附着细节、弧段覆盖信息和路径元数据。
- `entity-scene.ts`：批量带状几何、主轨材质、归一化深度、连续尾迹及装饰层聚焦；新增资源统一释放。
- `scene.ts`：全局与分类边界、相机拟合、图层统一聚焦、关系边 Shader、标签可见性和拾取一致性。
- `main.ts`、`style.css`：可用视口与面板布局联动；事件只调用场景命令，不持有另一套相机或材质状态。
- 现有模型测试及 `capture.ts`：补充实际几何、投影边界和交互检查，并生成同尺寸视觉对照。

状态与生命周期约束：

- 选择、悬停、面板布局和视口矩形属于当前预览页面。
- 相机过渡、渲染状态、几何和材质属于 `NeuralScene` / `NeuralEntity`，生命周期不超过页面；页面隐藏暂停，销毁时停止循环并释放资源。
- 快速连续聚焦采用“最新目标替换旧目标”，不得叠加独立动画循环；销毁后不执行迟到的尺寸或动画回调。
- 这里没有跨页面长期操作、IPC、子进程、下载或安装，不新增 singleton controller、Pinia、持久化或服务方法。没有模块边界例外授权；正式插件接入另行评审。

## 10. 优化顺序和阶段产物

1. **先修全局与分类镜头。** 交付默认、重置、分类和窄屏截图，确认完整边界和可用区域。镜头未稳定前不进行最终光感标定。
2. **只升级少量主环架。** 暂时保持碎片数量，验证近景厚度、远景轮廓、不同 DPR 和侧面效果。
3. **重新分配中层细节。** 优先迁移已有碎片，再按画面缺口补充；保留调整前后同镜头对照。
4. **改善流光与轨道衔接。** 减少流光头，使用连续尾迹及缺口掩码，在短视频中判断节奏。
5. **完成聚焦图层和标签。** 对照全局、分类、单点及返回过程，确认视觉状态完整恢复。
6. **统一验收。** 技术检查通过后，必须实际查看截图与连续动画，再决定视觉是否达到目标。

阶段失败范围：镜头拟合是后续视觉标定的必要依赖；主轨、中层和流光可以分别调整并保留已完成成果，不能因为某一项仍不理想而覆盖其他已确认结果。着色器编译、节点拾取或资源释放失败属于功能失败，必须修复；截图导出等附加动作失败只报告该动作，不重建或重放已完成的页面操作。没有自动安装、提权或额外业务重试。

## 11. 验收标准

### 11.1 同条件比较

固定随机种子、初始旋转、相机目标、动画时间、窗口内容区大小、DPR 和画质。对比图片不得通过单独放大某一版来制造密度差。至少使用 1440×900、1280×800 的桌面内容区，以及一组 768×1024 和 390×844 的窄屏内容区；桌面检查 DPR 1 和 2。

### 11.2 技术与行为

- 默认、重置、自动旋转和布局变化后，主体保守边界留在可用矩形内，不被 HUD 遮挡；允许用户主动缩放超出范围。
- 八类中每类的 20 个记忆节点、中枢及跨分类直接 semantic 对端在分类拟合后均进入可用范围，不展开对端的其他关系。
- 点击、双击、拖拽、滚轮和返回动作的拾取坐标与画面一致；快速切换不会回到旧相机目标。
- 无关边在分类聚焦后确实淡化；重置恢复全部图层状态；直接关系高亮不包含装饰线。
- 分类和记忆标识、membership 与 semantic 端点及数量保持不变；visual 边和装饰几何不伪装成业务关系。
- 减少动态、页面隐藏、重复进入和销毁后均符合既有生命周期，新增几何、材质、观察器与后处理资源得到释放。

### 11.3 必须人工查看的视觉结果

- **远看：** 首先读到一个完整金色全息体，至少能分辨少量主要环架及其内部结构，外壳不靠裁切撑满画面。
- **中距离：** 主轨、细轨和背景碎片形成明确层次，中层密度连续，同时保留空隙。
- **近看：** 主轨有亮芯与柔光边缘，横档和电路附着关系合理，没有带状几何裂缝、巨大尖角或实心球壳。
- **动态：** 连续观看至少 10 秒，流光沿结构运行，缺口过渡自然，没有明显圆点串；各运动组没有连接脱节。
- **聚焦：** 当前分类与直接关系清晰，其他类别退后；观察者不需要依靠右侧列表才能判断当前聚焦对象。

模型断言、截图像素差异、WebGL 无错误和构建通过都不能单独证明视觉验收完成。现有 HUD 的 `98.4%` 装饰数值也不能用作真实质量或验收指标。

### 11.4 性能边界

沿用批量 BufferGeometry，禁止每条细线、每个碎片或每条记忆创建独立 DOM/Mesh。主轨每个运动组最多合并为少量批次，背景细线保持现有批量方式；不增加持续运行的力导向布局。

首次以当前预览在同一设备、分辨率、DPR 和动作序列下建立基线，再比较修改后 10 秒旋转和交互的帧耗时、绘制调用和几何量。若持续帧耗时明显恶化，先减少中层装饰、尾迹和次要柔光，不牺牲当前分类节点或真实关系。记录测量条件和结果，不以单张截图声称性能流畅。

## 12. 后续实施时保留的判断空间

本方案建议保留现有 Three.js 和交互架构，新增主轨几何与图层策略；不需要为此安装新引擎或重写业务模型。轨道宽度、亮度、碎片数量和尾迹长度允许在以上方向内根据真实画面调整，实施者应记录最终选值和对照依据。
