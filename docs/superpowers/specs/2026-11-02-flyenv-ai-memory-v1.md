# FlyEnv AI Memory V1：开发者预览范围与验收

初稿：2026-11-02；修订：2026-11-03。状态：设计修订，尚未实现。

本文限定第一版做什么；数据与生命周期细节见 [目标设计](2026-11-02-flyenv-ai-memory-design.md)。后续能力不因目标设计提及就自动进入 V1。

## 1. 第一版要完成的使用闭环

在 FlyEnv 安装并启用插件，使用现有入口配置 Agent 的 MCP；复制 Memory Rules，按说明手工接入。Agent A 以项目路径保存一条决策；关闭会话后，Agent B 能查到摘要、按需读取完整正文。决策变化时能更新；删除完成后新发起的检索/读取不再获取内容，删除前已完成的读取响应可以晚到。

V1 是开发者预览，不宣称已完成一键接入。正式易用版的目标是 Codex/Claude Code 的 MCP 配置、无覆盖的规则接入和真实调用验证；需先核实各客户端支持方式，再提供自动接入。

文件集中存放在插件持久数据目录，项目代码目录保持无记忆文件。无需数据库、向量服务、模型配置或额外运行时；FlyEnv 退出后记忆 MCP 不可用。首轮真实 Agent 验收选择 Codex 和 Claude Code，其他 Agent 的通用 MCP 兼容性不等于已经验收。

## 2. V1 必须具备

- **存储**：每条 JSON 元数据、不可变 Markdown 正文、修订快照与最小删除凭据；project/global 两个范围，projects.json 原子提交且保存上一有效映射快照。
- **项目识别**：绝对项目根路径、realpath、稳定 UUID；同名目录隔离，worktree 独立。未知子目录返回已登记祖先候选，不自动合并或新建；确认独立时 store 显式 create_project=true。无祖先候选才可在首次写入登记，搜索不创建空项目。
- **一个所有者**：所有 UI/MCP 操作路由至同一专属 worker；稳定数据根互斥、进程持有的目录排他锁、按 scope 串行写入。
- **可靠写入**：正文先落盘、JSON 最后提交；revision 冲突检查、request_id 去重、崩溃后按凭据确定结果；旧记录不因附加通知失败被重放。
- **读取**：按 scope 懒加载元数据 Map，关键词/主题/tag 搜索；正文限制 16 KiB UTF-8，get 按所选 revision 一次完整返回，不提供正文 cursor。摘要搜索分页保留查询与范围代次约束。
- **五个工具**：search、get、store、update、forget。search 的空查询兼作列表，不增加 list；get 可读已知历史 revision，不另做历史管理 API。
- **最小管理页**：范围选择、摘要列表、搜索筛选、正文/来源、编辑/归档/删除、当前版本与修改原因；MCP 配置、规则文本、最近诊断、数据目录和备份步骤入口放同页。
- **可见的失败**：冲突、partial、unknown、busy 与真正成功区分；无法写入时不能声称已记住，未完成受管理文件清理不能声称完全删除。
- **可验证的记忆**：明确要求“记住”时调用保存并返回 ID/revision 或如实反馈失败；自主记忆统计重要事件覆盖率，不假定每次都能触发。增加自然查询评测与 MEMORY.md 对照。
- **最小诊断**：只记录操作、ID、结果、耗时、命中数量、错误码等白名单，最多保留最近 200 条易失记录；正文、摘要、查询原文和原始异常不进入通用审计日志。

保留历史快照用于追溯和已提交请求识别；不要求第一版同时提供历史时间线、差异比较和一键回滚。get 的选版/读文件/校验/固定快照复用 scope 协调队列，释放后再发网络响应；forget 排在其后时不能撤回已完成的快照，也不承诺 SSD 安全擦除。

## 3. 明确后置

- 多路径别名、多个 worktree 共享一个项目、目录搬家后重绑定。V1 新路径是新项目，旧数据可从管理页访问，不自动迁移或丢弃。
- 完整历史浏览、版本差异、回滚、批量删除、自动合并/反思。
- 正文分页、精细 LRU、持续性能监控和磁盘派生索引。正文回退/语义检索不预设必做，若效果实验失败，则在正式发布前按失败原因重新评估，不机械后置。
- MCP 主动工具变更通知、持久会话连接改造；V1 服务端目录更新后提示 Agent 刷新或重连。
- 各客户端自动安装/合并/卸载规则；预览先手工接入，正式易用版优先核实并完成两个主力 Agent 的自动接入，不能将“复制成功”标为“安装成功”。
- 全库备份恢复向导、在线导出、合并导入、定时备份。V1 提供打开数据目录和停用后复制/恢复的步骤，上一有效项目映射快照属于必要保护。
- 独立服务部署、多机器共享、多租户权限、任意存储 Provider、Dashboard。
- 万条数据性能调优、大规模评测平台及固定 p95 承诺；30～50 条标注的真实问题验证属于 V1。

## 4. 简化后的容量与维护策略

保留有界 Map，达到配置容量时按插入顺序释放空闲 scope，全部忙则 busy；不做精细 LRU。一个 scope 一个稳定协调对象，不能因缓存淘汰重建第二条队列；没有活跃/排队任务且无引用时才可回收。

撤回未经测量的 8 scope/1 万条/单 JSON 2 MiB 组合，先用真实样例测 JSON 总字节、current/history 占比、加载耗时及峰值内存，再固定预览默认限额。记录数不代表 I/O 或内存上限；即使只缓存 current，仍需解析文件内 history。原型也必须设单文件字节、scope 累计读取及缓存总量边界，并发有界；超出 scope 总预算返回容量错误，不能把部分结果当完整。坏/超大单条隔离并报告 partial，写入超限保留旧版；scope 总预算不阻断按 ID 删除和 pending 清理。

不常驻缓存 Markdown，不全项目扫描；tombstone 不进入检索 Map，按 ID 校验。pending 删除在 scope 首次访问时按同一队列恢复；未访问项目可继续有待清理文件，新读取仍被 tombstone 拒绝。成功删除后保留无内容回执，旧请求不能复活数据。

项目映射覆盖前保存上一有效快照，再原子提交新主文件并确认持久化；快照写入失败时不覆盖旧主文件。主文件损坏不初始化空库、不静默回退；恢复需停用并显式选择，快照缺少的后来项目列为未映射数据，保留目录而不猜测绑定。只有 global 不依赖损坏的项目映射，可独立服务。

## 5. 宿主只补必要能力

继续复用主进程 MCP 网关和既有 Agent 配置入口，记忆业务代码放在插件内；宿主补三项通用能力：

1. 校验声明式插件 MCP 工具清单，纳入工具开关、审批和派发；安装、禁用、升级后服务端目录立即更新。
2. 专属 worker 路由和数据根所有权，UI/MCP 进入同一入口；每次派发校验启用状态、安装代次和 worker 代次。
3. 关闭入口、排空请求、等待真实 exit 后再卸载或换代；新 worker 还需实际取得数据目录锁。

互斥键是稳定的规范数据目录，不含 generation；generation 是 owner 身份。当前 ForkItem.childExited 可在 kill 前被设置，stopPluginServices 无服务 PID 时也会直接返回，均不能代替真实退出等待。插件没有可安装的软件版本，不为 worker 伪造 SoftInstalled 或另建服务启动页。

目录锁/原子替换/真实退出在宿主最小验证阶段完成：进程退出释放锁、旧 worker 尚存时新宿主不能抢占、无法确认时拒绝写入。宿主单实例锁、PID 文件或超时删锁不能替代。此前的效果实验只能使用临时样例与单进程，不对正式数据提供共享写入；不新增系统服务、提权或多实例协作功能。

还需修正通用插件审计出口：当前 MCPAudit 截短字符串仍会保存正文和嵌套参数，不能直接沿用。成功、错误、未知/禁用工具、审批取消等所有分支均先白名单投影；Memory 使用有界易失诊断，不把内容写入 audit.log。宿主只认识声明式日志策略，不加入 Memory 业务类型；诊断失败不改变已完成操作。

## 6. 四步落地

1. **效果实验**：固定脱敏样例、单进程临时数据，验证检索和 Explicit/Automatic 规则；执行 30～50 条对照问题，不接正式用户库，不暴露尚不安全的并发写入。
2. **宿主最小验证**：极简插件验证工具出现、禁用拒绝、UI/MCP 同状态、换代等待；验证目录锁、文件原子替换/同步和真实退出，不同时开发完整记忆业务。
3. **可靠闭环**：文件提交、映射快照、revision/request_id、删除恢复及故障验证；接五个工具、基础页面、诊断、规则文本及备份步骤入口。
4. **日常预览与正式体验**：两个主力 Agent 双向跨会话及长任务使用；按结果修正召回与保存行为，按平台验收。正式易用版再补经核实的一键接入与真实调用验证。

这四步是开发顺序，当前交付仍是设计文档，不表示代码、锁原型或验证已完成。

## 7. V1 完成标准

- Codex 保存、Claude Code 新会话读取；反向也成功。重启 FlyEnv 后仍能取回，实际调用的 project_path 与记忆范围正确。
- 并发不同记录不丢失；同一 request_id 重试不重复；相同 expected_revision 并发更新只有一个成功。
- 16 KiB UTF-8 上限对中文/emoji 正确，超限拒绝不覆盖旧版；get 整条返回一个版本，不截断、不接受正文 cursor。
- get 先完成逻辑读取允许响应晚于 forget 送达；forget 先提交则后续逻辑读取 deleted，成功响应后新 get 也 deleted；不假报能撤回旧响应或安全擦除。
- forget 同请求同参数完成后返回原 success，同请求改参数冲突；另一请求重复删除返回 already_deleted。清理失败返回 partial，重试/首次访问恢复后变为完成。
- 文件提交关键点注入异常后，只出现完整旧版、完整新版或明确未知状态；未成功提交不提前发布缓存，原文缺失/损坏不伪报成功。
- worker 请求已结算但实际未 exit 时不能创建替代者；宿主异常退出但旧 worker 尚存时数据锁拒绝新所有者，退出后才能接管。
- 更新/卸载与调用竞争时，不存在旧工具绕过代次检查或两个写入者；审批等待后也重新检查。页面重入、重复点击、监听清理和终态通知符合 controller 合同。
- 根目录/子目录启动能通过候选提示找到已确认根；独立子项目不被合并。同名路径、global、软链接/junction、大小写和特殊字符符合范围规则。
- 主映射与上一版快照的失败边界可验证；损坏不建空库，恢复缺项明确列出且数据仍在。坏记忆不拖垮其他记录，global 不因项目映射损坏失效。
- 懒加载、有界文件读取/缓存、单次并发加载、协调对象释放及超限有覆盖；不读所有 MD，不扫描未访问项目。用真实与千条生成数据测量后确定默认容量，不将条数冒充内存预算。
- 诊断能区分观测到的调用、结果及命中数量，未观测调用不能直接证明 Agent 没调用；Agent 自报身份明确标记。所有审计分支都不持久记录正文/摘要/查询或原始异常，诊断失败不重放主操作。
- 用 30～50 条预先标注的问题测自然改写、中英文、技术标识、历史事件、更新与无答案项；对有答案项计算 Recall@5，无答案项单独看误召回，工具原始查询与 Agent 扩词后的效果分别报告。85% 仅为待校准建议，关键场景失败必须分析修正。
- Explicit 测试每次有真实 ID/revision 或明确未保存/未知说明，成功可读回；Automatic 用标注的重要事件机会统计保存覆盖率与误存，包含长任务和上下文变化，不能假定规则必定执行。
- 与 MEMORY.md 使用相同资料、问题、模型和上下文预算对照，不编造来源、不预设 token 节省。跨 Agent/并发这些基线不具备的能力单列；验收样例与调试样例分开。

仅对完成原生文件系统、锁和进程生命周期验收的平台声明支持；macOS 验证不能替代 Windows/Linux。功能后置不包括省略这些数据可靠性验证，也不把杀进程恢复等同于所有断电场景保证。
