# llama.cpp 版本管理并行下载

## 范围与原因

按用户要求移除版本管理卡片 footer，并允许不同版本同时下载。
原实现的页面 `busy`、控制器单个 `runtimeOperation` 和 fork 全局
`runtimeMutationInProgress` 三处一起串行化所有版本；安装器已经按版本身份
生成独立安装目录和随机 staging 目录，不需要全局下载锁。

## 操作契约与实施计划

- 页面仅拥有渠道选择、版本目录加载和删除确认；绑定每行对应的控制器操作。
- renderer 单例 `LlamaCppController` 持有按安装目录身份索引的完整操作状态，
  包括不可变安装参数、IPC、进度、终态、错误通知、刷新和重入保护。
  生命周期从点击开始直到 IPC 终态及列表刷新结束，页面销毁不影响任务。
- `code: 200` 是非终态进度；每版本独立更新。IPC 成功/失败时解绑该请求监听。
  成功、失败终态保留，失败后允许重试；安装和卸载同版本共用锁。
- fork 拥有按规范化目标路径索引的修改锁，在 `finally` 释放。
  不同版本可同时修改；同版本重复安装、安装与删除冲突必须拒绝。
- 服务启动仍使用既有全局互斥，避免修改活动版本时停止服务与新启动交叉。
  修改活动版本前仍必须成功停止该服务；未修改的运行服务不会被其他版本下载停止。
  不新增服务启动/停止流程或伴随进程。
- 下载、验证、安装、卸载是必要步骤；失败仅影响当前版本，保留其他版本的结果。
  已完成操作后的列表刷新是附加步骤，失败只通知刷新错误，保留操作成功及结果。
  刷新按顺序进行，并等待已有扫描完成后发起新扫描，避免加入过期快照。
- 无新 Pinia、共享配置、持久化数据或公共模块类型；所有新增状态在插件目录内。
  不需要约束例外授权。

## 验证与 review

- 控制器回归覆盖双版本同时执行、独立响应式进度、同版本安装/卸载重入、
  一个失败时另一任务继续、失败重试、终态保留、刷新完成前保持忙碌、
  刷新串行化及刷新失败不否定已完成安装。
- fork 回归覆盖双版本并发、同目标安装/卸载/启动冲突、单项失败释放锁、
  失败不释放兄弟任务的锁及活动版本停止失败传播。
- 复用传输层终态监听清理测试；更新 renderer 操作边界检查和每版本状态绑定。
- 按失败边界技能 review：重复操作的提前拒绝仅影响对应请求；安装/删除错误
  不吞掉，兄弟任务不取消；刷新错误不重放安装、不覆盖成功终态。

验收：`yarn test:llamacpp-plugin`、`yarn test:renderer-operation-boundaries`、
`yarn test:service-stop-snapshot`、`yarn plugin:test llamacpp` 均通过；
改动文件 ESLint（保留原有格式，关闭 Prettier 规则）及 `git diff --check` 通过。
插件测试实际编译 renderer/fork 并检查入口，未发布插件或执行真实公网版本下载。

全项目 `vue-tsc --noEmit` 仍有 65 条既有诊断；本次控制器、fork 和测试
无诊断。版本页的 `ModuleInstalledItem.flag` 诊断来自原有显示代码（修改前
也直接读取该属性），未扩展公共服务类型。
