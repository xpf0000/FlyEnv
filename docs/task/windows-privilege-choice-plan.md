# Windows 权限授权方式改造方案

日期：2026-09-30。

状态：核心代码已实施，并完成本地针对性回归；真实 UAC、跨账户凭据、SYSTEM 任务停用及企业策略验证尚待实机验收。实施结果见第 11 节。

新增及调整代码的完整说明、Helper/UAC 当前全链路及本轮补查修正，集中见 [Windows 权限方式实现与代码复查说明](windows-privilege-choice-implementation.md)。

## 1. 目标与已确认交互

Windows 上首次真正需要管理员权限时，明确解释 UAC 与帮助程序两种方式，由用户自己选择，并提示后续可在设置中重新选择。

- 日常启动、页面浏览、普通查询和当前权限足够的操作直接执行。
- 未选择方式且确需提权时，先展示选择窗口，选择后继续当前操作。
- 关闭选择窗口取消当前操作，不保存选择；下次需要提权时再询问。
- 已提升为管理员进程的 FlyEnv 直接执行，跳过帮助程序检查、安装和 UAC；不因此写入授权方式偏好。
- 用户选择的方式持续有效。帮助程序恢复、操作失败和管理员运行均不自动修改偏好。
- UAC 模式的正常运行链路不检查、连接、安装、启动或修复帮助程序。

管理员身份按当前进程实际权限令牌判断。账户属于 Administrators 组，不代表当前 FlyEnv 已提升。主进程和执行操作的 fork 均应确认自身执行权限，不能信任 renderer 传来的布尔值。

此次收益是减少帮助程序常驻、SYSTEM 计划任务及反复巡检。修改 hosts、系统环境变量、证书等必要操作仍可能被企业策略审计或阻止；UAC 不提供“免风控”保证。

## 2. 当前实现依据

用户反馈截图：[企业风控记录](./7e5c45f68d567531af2d047e0f0a503b.png)。记录涉及计划任务查询、账户 SID 和环境路径读取；它没有展示完整规则、命令或阻断原因，不能据此断言全部告警由帮助程序导致。

已确认的实现问题：

- `src/render/components/Setup/WindowsElevationMethod/index.vue` 已有两种方式和设置入口，可在此基础上完善交互。
- `src/shared/WindowsHelperState.ts` 把缺失配置解释为 `helper`；`ConfigManager.ts` 会补写默认值，因此已有 `helper` 字段不能证明用户明确选择过。
- `src/fork/Helper.ts` 在 UAC 模式下仍让 Shell 集成、数据目录恢复优先检查帮助程序。
- `src/shared/Process.win.ts` 查询进程前调用 `AppHelperCheck()`；该检查会读取身份、校验任务、检查版本和健康。
- `src/shared/Process.ts` 的结束进程等操作也有帮助程序优先分支，需要审查 Windows 调用链。
- `src/main/Application.ts` 在帮助程序就绪后把偏好写回 `helper`，与持久保存用户选择冲突。
- `src/shared/WindowsHelperFallback.ts` 已有部分 UAC 操作，但读取文件、结束进程、清理端口、查询证书等覆盖和返回结果仍需补齐。
- `src/fork/module/Tool/process.ts` 等入口吞掉部分错误并返回成功，无法正确表达取消授权或执行失败。
- `src/shared/Sudo.ts` 的 Windows 通用链路使用临时 BAT 和结果文件；v27 安装器已有跨账户命名管道结果通道，可作为改造参考。

## 3. 用户界面

### 3.1 首次选择窗口

标题：**选择权限授权方式**。

说明：**当前操作「{操作名称}」需要管理员权限，请选择授权方式。**

两个选项均不预选，不标记默认推荐项：

- **UAC 授权**：需要管理员权限时，由 Windows 请求确认或管理员凭据，无需安装常驻帮助程序。
- **帮助程序**：安装在后台运行的权限帮助程序，后续支持的权限操作通常无需重复确认。安装涉及系统计划任务，企业设备建议先确认管理政策。

底部提示：**选择后将记住您的设置，后续可在「设置 → 权限授权方式」中重新选择。**

按钮：**使用 UAC 授权**、**使用帮助程序**、**取消**。

点选方式并完成配置保存后，继续当前操作。选择帮助程序即授权为本次操作安装或修复当前账户的帮助程序，实际安装仍需 Windows UAC 批准。关闭窗口、按 Escape 和取消按钮含义一致。

用户选择 UAC 后取消原生 UAC，取消的是本次操作，已保存的方式仍为 UAC。选择帮助程序后取消安装 UAC，记住帮助程序偏好并显示未就绪，下次由用户决定重试或在设置中切换。

### 3.2 设置入口

沿用设置中的权限方式组件，显示 UAC、帮助程序或“尚未选择”。设置页主动选择与首次选择使用同一控制器和保存接口。

- UAC：说明按需授权；仅在确需提权时请求 Windows 授权。
- 帮助程序：说明常驻和计划任务，保留安装/修复按钮及就绪状态。
- 管理员运行：显示“FlyEnv 当前以管理员权限运行，本次运行直接执行权限操作”，同时展示已保存偏好；用户仍可修改下次普通权限运行所用的方式。
- 切换处理中禁用重复操作，展示进度和最终结果。
- 授权窗口与设置窗口只展示业务操作说明，不暴露内部方法名、IPC 名称、协议细节。

### 3.3 已安装帮助程序的停用

仅修改偏好不足以结束旧帮助程序，必须提供明确停用流程。

使用 UAC 的说明增加：**如果此前安装过帮助程序，可停用当前账户的帮助程序，避免它继续在后台运行；停用可能需要一次 UAC 授权。** 设置中提供“停用帮助程序”动作。

旧用户首次选择 UAC 或从帮助程序切换到 UAC 时，自动停用当前账户此前安装的帮助程序，不提供额外勾选项或自动停用说明。确认选择即授权执行这次定向停用，需要管理员权限时仍由 Windows 授权。

- 停用只处理可验证属于当前账户的 FlyEnv 帮助程序任务和进程：停止并禁用任务，阻止下次登录自动启动。
- 不按进程名批量结束、不处理其他 SID 实例、不扫描全部计划任务、不修改普通 FlyEnv 开机启动任务。
- 保留受保护的安装文件以便重新启用；“停用”不显示为“卸载”。
- 在用户确认停用后才读取原始 SID 并定向校验当前实例；这次迁移操作允许查询目标任务，正常 UAC 运行不再巡检帮助程序。
- 拒绝停用授权或停用失败时，UAC 偏好仍保留，但明确提示“授权方式已切换，旧帮助程序尚未停用”，提供重试入口，不能报告已消除常驻。
- 用户取消勾选时说明旧帮助程序可能继续运行。FlyEnv 的新权限请求仍只走 UAC。
- 对无法验证归属的旧版机器级任务，说明需要独立处理；不得为清理它们扩大到其他账户。

## 4. 持久化与升级迁移

继续使用已有应用级偏好 `setup.windowsElevationMethod`，值保持 `helper | uac`。新增应用级确认标记 `setup.windowsElevationChoiceVersion`，首版为 `1`，默认缺失，不在初始化时补成已确认。

该字段属于现有全局设置的用户授权偏好，并非新业务模块数据；不新增 Pinia store。业务模块自己的数据仍遵守 StorageGetAsync/StorageSetAsync 规则。

- 标记为 `1`：方式已经明确选择，后续权限操作直接按偏好执行。
- 标记缺失：视为尚未完成本轮明确选择。已有 method 只能作为旧配置展示，不用于默认授权。
- 新用户与旧用户均只在首次实际提权前完成一次选择，升级启动时不集中弹窗。
- 旧版本已明确选过 UAC 的用户也会被重新说明一次，因为目前没有可靠标记区分手动选择和自动回退；窗口可展示“此前设置：UAC”，但不预选。
- 选择方式与确认标记由主进程一次提交；保存失败则不执行权限操作，允许重试。
- 管理员运行不生成确认标记；以后普通权限运行首次确需提权时仍有选择机会。
- renderer 普通配置保存不得以过期快照覆盖已提交的方式和标记。该组字段由专用 IPC 管理，普通 saveConfig 路径保留主进程最新值。
- 保存成功后广播版本号和偏好，更新主窗口、托盘以及所有存活 fork；新 fork 从主进程获得最新快照。不能仅改 `global.Server` 后等待下一条请求刷新。

## 5. 统一权限路由

权限入口采用以下顺序：

1. 以经过验证的参数判断操作是否可在当前权限下完成；可完成时直接执行。
2. 确认实际执行进程已提升时，直接执行同一业务动作，不访问帮助程序。
3. 当前权限不足且属于明确可恢复的权限错误，进入授权协调器；路径不存在、文件锁、格式错误等不触发选择或提权。
4. 尚未选择时等待首次选择完成；已有选择则使用最新偏好。
5. UAC 模式走独立的按需提权执行器；帮助程序模式走现有受验证的安装、健康检查和 RPC。
6. 返回真实终态，保留用户偏好；不因失败自动切换授权方式。

对可以明确识别的系统写操作，允许直接进入第 3 步，避免先执行造成部分修改。对可能部分完成的操作，返回已完成步骤，再由业务控制器决定后续处理，不能把整个业务流程重新执行一遍。

### 5.1 首次选择与并发请求

主进程维护一个首次选择 Promise，多窗口和多 fork 共享一次选择。等待的每个操作具有自己的 requestId、参数快照、来源和截止时间。

- 相同 requestId 只执行一次；不同业务请求共享选择结果，仍保留各自生命周期。
- 关闭选择窗口终止所有等待该次选择的请求；不形成无限重弹。
- 选择完成后只继续尚有效的请求；取消、超时、参数前置状态已变化的请求不执行。
- 主窗口不存在时不丢弃请求：交互式启动恢复等待窗口可用，再显示具体修复说明；后台任务返回需要用户配置的错误。
- 自动刷新、无人值守任务和关闭应用清理不能主动弹首次选择或原生 UAC；返回需要授权的状态，通过既有通知说明受影响操作。
- 托盘和 MCP 来源显式传递是否允许交互；没有交互上下文时返回类型化错误，由调用方提示用户到设置完成选择。
- 对业务主动取消和窗口重建做注销处理；页面卸载不自动取消已经提交的有效操作，操作状态归控制器。

### 5.2 启动恢复与退出清理

`src/main/utils/ServerPath.ts` 的数据目录恢复也走统一路由。普通创建目录成功时不访问权限系统；真实权限不足时，在主窗口准备后显示“修复 FlyEnv 数据目录权限”，不能在窗口创建前等待选择而形成启动死锁。

主窗口应能在数据目录未就绪时展示恢复入口；依赖目录的服务操作继续受 DataDirectoryReady 约束。取消修复允许进入可用界面，并明确受影响功能。

`ServerManager.cleanHosts()` 等退出路径应在实际退出前完成必要清理。需要新授权时在可交互窗口尚存的阶段提示；无交互上下文时记录未完成项，不循环弹窗、不声称已清理，退出后由下次显式操作处理。

## 6. UAC 执行与操作覆盖

### 6.1 执行器

新增 Windows 专用执行入口，将实际业务动作与“直接执行 / UAC 提升”分开。管理员直执行与 UAC 执行复用参数验证、动作实现和结果格式，不能只把 `Helper.send()` 跳过后返回成功。

参考 `WindowsHelperInstaller.ts` 的跨账户结果通道，抽取通用 Windows 提权基础设施，安装器作为其调用方。安装专用行为保留在安装器，避免把通用 Sudo 其他平台行为一起改动。

- 使用系统 PowerShell 绝对路径、NoProfile、固定模块环境；参数按结构化数据传递，明确工作目录和允许的环境变量。
- 提权之前捕获原用户的必要身份和业务路径；提权后仍使用原用户的资料路径、配置路径和任务目标，不把批准授权的管理员当成业务用户。
- 结果包含 requestId/nonce、真实退出码、业务返回值及有界输出；管道访问与对端校验覆盖原用户和批准 UAC 的管理员，不能以随机管道名替代身份边界。
- 不默认依赖提权管理员能读取原用户 TEMP 中的脚本、输入和状态文件；较大输入采用有访问控制的一次性通道，明确大小限制和清理生命周期。
- 区分取消、启动失败、动作失败、通信失败及执行状态不确定的超时。
- 超时不等于子进程已退出，不立刻删除仍被它使用的载荷。保留有限迟到结果回收机制，查询实际结果后再允许重试。
- UAC 请求按队列发起；同一业务操作的相关步骤可以合并成一次授权，不为互不相关的操作建立无限期管理员会话。
- 实际业务动作结束后执行器退出，不注册 SYSTEM 帮助程序任务，不建立常驻提权服务。
- 编码或压缩 PowerShell 仍可能触发企业策略；抽取执行器不能据此宣称降低了脚本行为告警，需在企业策略环境验证。

### 6.2 需要覆盖的 Windows 能力

逐项对照 `src/helper-go/contract/helper-contract.json` 和 Windows 可达调用链登记输入、返回类型、直接执行、UAC、帮助程序三条路径。

- 文件读取、文本/二进制写入及删除：普通权限优先；仅对权限不足请求授权；保留文件编码、路径范围和真实返回值。
- hosts 修改及 DNS 刷新：归同一次站点业务操作，避免每次文件写入单独授权；处理刷新失败和已写入状态。
- 数据目录权限恢复：只修复明确的 FlyEnv 数据目录；跨账户授权时 ACL 仍授予原始用户。
- PowerShell 集成：优先处理原用户可写的 profile；需要权限的写入走所选方式；允许完全未安装帮助程序时完成合法操作。
- 环境变量与 PATH：保留既有目标作用域、冲突检查和变更广播；正常读取不检查帮助程序。
- 普通 FlyEnv 开机启动：与帮助程序任务独立，不把 UAC 模式描述为“绝不使用任何计划任务”；仅在用户启用相关功能时操作。
- 证书查询、导入与删除（以当前 Windows 可达功能为准）：查询优先普通权限，明确实际证书存储位置及导入结果。
- 进程查询、端口查询、结束进程、清理端口：查询优先普通权限；结束自有进程直接执行；真实权限不足才授权。结束进程前复核目标 PID 与进程身份，避免 PID 复用造成误操作。
- Windows 不可达的 Unix 专用方法继续由平台边界隔离，不为了扩大 UAC 覆盖而改变其他平台功能。

现有 fallback 的路径策略部分依赖帮助程序生成的 allowed-roots。UAC 和管理员执行必须能在从未安装帮助程序的设备上工作：采用当前应用明确配置的规范业务根目录，并在执行侧复核允许动作和目标路径，保留系统敏感路径限制、reparse-point 检查和必要 ACL 防护。不能通过取消全部校验来解决依赖。

普通读取无法获得其他账户的完整进程信息时，应返回能力受限状态；不为页面自动刷新读取完整信息而循环弹 UAC。

## 7. 状态所有权与操作契约

本改造属于现有应用级权限功能，不新增业务模块、Pinia store或服务启停工作流；各模块继续使用 ModuleInstalledItem.start()/stop()/restart()，模块参数留在各模块内。无新模块约束例外。

renderer 采用权限功能目录内的普通 singleton controller，通过 reactiveBind 暴露状态；页面绑定状态并调用命令。既有 `src/render/store/helper.ts` 实际为单例 class，可继续拥有安装操作。

主进程的权限协调器拥有跨窗口选择、可信偏好提交、版本广播、请求队列；fork 模块继续拥有服务子进程、PID/端口、健康及伴随进程关闭。renderer 不作为进程存活依据。

### 7.1 首次选择操作

- Owner：主进程权限协调器；renderer 权限控制器负责界面和 IPC。
- Lifetime：从第一个有效权限请求到选择提交或取消；跨页面、跨 fork。
- Start：确需提权且确认标记缺失。
- Intermediate：等待窗口、显示选择、保存偏好；沿用 IPC 中间码时 `code: 200` 非终态。
- Terminal：choiceCommitted、choiceCancelled、choiceSaveFailed、requestExpired、applicationClosed。
- Duplicate：全局共享一次选择，相同 requestId 去重。
- Service interaction：选择本身不启动或结束业务服务；终态后恢复有效请求。
- Lifecycle tests：并发、页面重入、多窗口、保存失败、取消、窗口重建、应用退出和过期请求不执行。

### 7.2 UAC 业务执行

- Owner：原业务控制器/fork 模块持有业务生命周期；主进程协调授权队列；执行器持有提权子进程和结果通道。
- Lifetime：业务参数验证至真实结果或不确定超时后的有限资源回收。
- Start：有效请求已按权限和偏好路由到 UAC。
- Intermediate：queued、waitingForUac、executing、stepCompleted。
- Terminal：success、uacCancelled、launchFailed、executionFailed、resultChannelFailed、timeoutUnknown。
- Duplicate：相同请求共享结果；终态不确定时禁止未经核实的重复执行。
- Service interaction：实际服务和伴随进程由原 fork 模块管理，执行器退出不表示服务停止。
- Lifecycle tests：跨账户、结果类型、权限拒绝、部分完成、超时迟到、重试、防重、父子进程关闭和结果通道清理。

### 7.3 帮助程序安装/修复

- Owner：既有 renderer Helper 单例与 main AppHelper 单例。
- Lifetime：用户选择或显式修复至安装失败、取消或健康检查通过。
- Start：帮助程序偏好下的有效权限请求且 helper 不可用，或用户点击修复。
- Intermediate：checking、recovering、installing、waitingForHealth；安装脚本完成不等于健康终态。
- Terminal：ready、cancelled、failed、timeoutUnknown。
- Duplicate：复用现有 installation Promise；切换方式期间禁止交叉安装和停用。
- Service interaction：就绪后继续待执行动作；失败不启动依赖操作、不修改为 UAC。
- Lifecycle tests：现有 v27 回归、取消后偏好保留、页切换进度、修复后不覆盖选择和并发请求。

### 7.4 设置切换及帮助程序停用

- Owner：renderer 权限 singleton controller；main 协调器负责偏好和当前 SID 的定向停用。
- Lifetime：用户确认切换/停用至配置广播及停用结果。
- Start：设置点击或首次选择 UAC 并确认停用选项。
- Intermediate：saving、waitingForExistingOperation、waitingForUac、stoppingHelper、disablingTask、broadcasting。
- Terminal：success、cancelled、saveFailed、helperDisableFailed；方式已保存但停用失败时分别展示两个结果。
- Duplicate：同一切换共享 Promise，处理中禁用按钮；不终止已开始的业务写操作。
- Service interaction：已有请求固定使用启动时的方式，待执行请求重新验证并使用新版本；等在途 helper RPC 完成后才停用，不停止业务服务或其他 SID 的 helper。
- Lifecycle tests：快速重复点击、跨窗口旧配置覆盖、fork 热同步、已有请求执行期间切换、停用拒绝/失败、其他用户实例隔离。

### 7.5 数据目录恢复

- Owner：main 既有 ServerPath/ServerManager 恢复流程；界面进度由权限控制器持有。
- Lifetime：创建目录遇到真实权限不足至目录重新校验完成。
- Start：明确权限错误，且目标为合法 FlyEnv 数据目录。
- Intermediate：waitingForWindow、waitingForChoice、recovering、verifyingDirectories。
- Terminal：ready、cancelled、failed、authorizationRequired。
- Duplicate：继续按数据根目录共享一次恢复 Promise。
- Service interaction：目录 ready 后才恢复依赖服务，修复失败不伪造 DataDirectoryReady。
- Lifecycle tests：窗口创建前触发、取消后进入界面、页面重入、跨账户 ACL、恢复重试与并发服务启动。

## 8. 实施顺序与修改范围

### 阶段一：可信权限状态与首次选择

1. 增加当前执行进程权限检测、确认标记与权限快照版本；修改 WindowsHelperState、ConfigManager、ServerManager 和相关类型。
2. 增加主进程协调器及专用 IPC，处理首次选择、防重、提交、广播和后台请求。
3. 增加 renderer 权限单例、首次选择窗口及设置状态，接入既有 GlobalIPCOn 和帮助程序单例。
4. 移除帮助程序就绪后自动写回 helper 的行为；普通 saveConfig 不覆盖权限偏好。
5. 调整启动数据目录恢复顺序，确保窗口可用且无启动等待环。

阶段完成条件：首次选择、保存、管理员跳过和跨进程同步完整；此时尚不发布“UAC 完整替代帮助程序”的承诺。

### 阶段二：独立执行链与能力补齐

1. 抽取 Windows 提权执行基础设施，增加管理员直执行及结构化业务结果。
2. 对 Windows 可达操作建立覆盖清单，复用并完善现有 fallback 参数/路径策略。
3. 统一 Helper.ts、Process.win.ts、Process.ts、Fn.ts、main/utils、Tool.win、Host、AppNodeFn 等入口；移除 UAC 模式下 helper-first 分支和隐藏检查。
4. 收紧相关吞错路径：取消、失败、不支持和受限查询均返回正确结果。
5. 合并同一业务操作的权限步骤，落实服务模块原有进程所有权。

阶段完成条件：从未安装帮助程序的普通账户与已提升账户均能完成所有受支持的 Windows 功能；UAC 日常操作无帮助程序巡检。

### 阶段三：停用迁移与交付

1. 实现当前 SID 帮助程序定向停用，以及再次选择 helper 时的重新启用/修复。
2. 完成旧配置首次确认、设置切换、多窗口与长寿命 fork 一致性。
3. 更新全部受支持语言，说明首次选择、管理员直执行、取消授权、部分失败和停用结果。
4. 汇总代码回归与 Windows VM/企业策略实测证据，明确已验证和未验证环境后发布。

若修改 Go helper 或实际协议/行为，实施时同步 Go 与 TypeScript 版本并重新打包；如果仅调整 TypeScript 调用链，则依据最终改动范围确定是否升版，不在方案阶段先改版本。

## 9. 验收标准

实施时执行必要的针对性测试与手动验证。本方案阶段不运行测试。

交互与路由：

- 新用户普通启动、浏览和查询均不弹窗；首次实际提权出现两个清楚选项，后续可在设置重新选择。
- 关闭选择不保存；取消原生 UAC 不清除已选方式；安装失败不自动改成 UAC。
- 已提升运行时，不选择、不安装、不查询帮助程序、不再次请求 UAC；恢复普通运行后仍使用保存偏好或等待首次选择。
- 并发 5 个有效权限请求只出现一次选择窗口；重复请求只执行一次；取消和超时请求不被迟到选择恢复。
- renderer 卸载、重入或主窗口重建不丢失有效进度，所有终态清理 IPC/listener/timer。
- 设置切换立即同步主窗口、托盘和存活 fork，普通配置保存不能覆盖最新权限偏好。

功能与兼容：

- 在完全未安装 helper 的设备上，逐项验证文件、hosts、DNS、数据目录、Shell 集成、PATH、环境变量、证书、开机启动和进程/端口操作。
- 读取结果、布尔结果、查询数组及 Shell 集成结构化结果与现有业务契约一致。
- 普通用户以另一管理员账户批准 UAC，仍正确使用原用户路径、配置和 ACL。
- 中文、空格、单引号、百分号、感叹号路径，以及较大载荷、拒绝授权、文件锁、缺失路径、管道受限和迟到结果分别覆盖。
- 检查 SYSTEM helper 曾创建的业务文件权限，在 UAC 与管理员模式下仍可访问；仅针对合法业务根定向修复，不放宽 helper 安装/key/allowed-roots 安全策略。
- 帮助程序 v27 的主程序/备份指纹一致性、来源规则、SID 隔离、安装锁和无版本回滚策略通过既有回归。
- macOS/Linux 不受 Windows 权限选择逻辑影响。

系统访问与进程生命周期：

- UAC 模式正常启动、进程页面刷新、服务启停和设置浏览均不访问帮助程序任务、不检查其 key/指纹、不连接 helper pipe、不自动修复。
- 原用户 SID 和环境路径只按业务必要性获取并缓存；正常功能依赖的读取不能被宣称全部消除。
- 用户确认停用后，仅当前 SID 的 helper 进程结束且任务禁用；其他用户 helper、普通 FlyEnv 开机启动和业务服务继续正常。
- 卸载/停用失败、部分完成和超时不能返回虚假成功；重试不产生重复系统修改。
- 业务服务/伴随进程的关闭仍归 fork 模块；提权执行器正常结束后无额外常驻进程。
- 企业策略验证记录实际发起的权限动作与拦截结果，不只以“UAC 窗口正常出现”作为通过依据。

## 11. 本次实施记录（2026-09-30）

### 已实施

- 首次实际权限请求通过主进程 `WindowsPrivilegeCoordinator` 统一询问；旧配置没有 `windowsElevationChoiceVersion=1` 时仍需用户明确选择。关闭窗口取消等待操作，保存失败不放行。
- 设置和首次窗口由 `WindowsElevationMethod/Controller.ts` 持有异步操作，页面仅持有选择输入。重复窗口、重复 IPC、过期窗口、进度消息、终态监听与定时器清理已覆盖。
- `WindowsPrivilegeOperation.ts` 在 Windows 业务请求访问帮助程序前分流：当前权限足够则直接执行；实际权限不足才询问并走 UAC 或帮助程序。机器级写入直接进入授权分流。
- 主进程与执行 fork 各自检测有效管理员令牌。已提升执行不检查帮助程序，也不写入用户偏好。
- UAC 使用 `WindowsElevation.ts` 一次性管道执行器，固定启动脚本与受验证动作分开传递；返回结构化结果，不依赖另一个管理员账户的临时文件。缺失可信结果按结果不确定处理，阻止同一动作盲目重试，保留有限的迟到结果接收窗口。
- 文件、hosts、DNS、数据目录权限、PowerShell 集成、PATH、系统环境变量、证书、开机启动、PID/端口操作均有独立动作构建。数据目录恢复不允许覆盖 Windows 系统目录或帮助程序安装目录；提权后再次检查路径中的重解析点。
- 进程结束记录目标创建时间并在执行前重新核验，防止等待 UAC 时 PID 被复用。服务、语言项目、自定义模块、PHP、Temporal 与 Neo4j 的 Windows 停止链路保留错误，取消授权不再作为停止成功返回。
- 证书生成后取消信任操作，重试会重新核验信任状态；通过证书指纹区分同名旧证书。
- 新增 `app-fork-background:` 请求路径。自动启动通过原有服务生命周期传递后台意图；MCP 与后台任务不打开首次选择窗口、不请求 UAC、不隐式安装/修复帮助程序。已明确选择帮助程序时允许使用现有健康实例。
- 设置变更带 revision 广播到主窗口、托盘与存活 fork。普通整份配置保存保护授权字段，避免旧快照覆盖新偏好。
- 明确勾选停用选项后，定向验证并停用当前 SID 对应的帮助程序任务和实例；停用失败保留 UAC 偏好并显示提示。停用不删除安装文件、不关闭业务服务，重新选择帮助程序可修复启用。该入口处理当前 per-SID 实例，不清理无法确认归属的旧机器级任务。
- 33 种内置语言补齐首次选择、两种方式、设置重选、管理员运行、停用与失败说明。细分动作名称在尚无本地译文时使用既有英文回退。
