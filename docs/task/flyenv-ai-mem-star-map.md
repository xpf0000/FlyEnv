# FlyEnv AI Memory：3D 神经网络记忆体可视化改版

## 一、改版目标

目前 FlyEnv AI Memory 插件已经实现了记忆星图功能，但现有视觉效果比较简单，节点分布更接近传统的平面关系图。

现在需要重新设计并实现记忆星图，将其改造成一个具有强烈科技感、空间感和生命感的 **3D AI 神经网络记忆体（3D Neural Memory Network）**。

视觉风格参考《钢铁侠》中 J.A.R.V.I.S. 的全息数据可视化效果，尤其是由大量光点、能量线、复杂结构和动态数据自然聚合形成的悬浮球形全息系统。

注意：

- 不要在中心放置明显的人类大脑模型。
- 不要在中心放置巨大的“AI 记忆体”文字或 Logo。
- 不要把八种记忆分类简单排列成规则的八边形。
- 不要制作成普通太阳系、行星轨道或星座图。
- 不要只是给现有 2D 星图增加发光、阴影和粒子。

**核心视觉概念：无数记忆节点通过神经连接相互关联，最终自然聚合成一个庞大、复杂、不断演化的 3D AI 记忆网络。**

整个记忆体应该看起来像一个拥有生命力的智能神经系统，而不只是一个静态数据图表。

## 二、核心结构：八个主神经节点

目前 AI Memory 有八种记忆分类：

1. 偏好（Preference）
2. 事实（Fact）
3. 事件（Event）
4. 流程经验（Procedure）
5. 项目状态（Project State）
6. 决策（Decision）
7. 观察（Observation）
8. 笔记（Note）

这八种分类对应八个 **主神经节点（Primary Neural Hubs）**。

每种分类使用独立的主题颜色。

建议配色：

| 分类   | 颜色  | HEX       |
| ---- | --- | --------- |
| 偏好   | 紫色  | `#A855F7` |
| 事实   | 蓝色  | `#3B82F6` |
| 事件   | 珊瑚红 | `#FF647C` |
| 流程经验 | 绿色  | `#22D3A0` |
| 项目状态 | 青色  | `#06D6F0` |
| 决策   | 金色  | `#FFB830` |
| 观察   | 靛紫色 | `#818CF8` |
| 笔记   | 粉色  | `#EC4899` |

这些颜色需要贯穿整个可视化系统，包括主节点、子节点、连接线、选中效果和筛选状态。

### 2.1 主神经节点

每个主神经节点代表一种记忆分类。

视觉要求：

- 主节点比普通记忆节点更大、更亮。
- 可以由一个高亮能量核心和多个环绕的结构层构成。
- 具有柔和的 Glow、Halo 和脉冲效果。
- 不同分类具有独立的颜色。
- 在整体空间中自然分布，而不是机械地等距排列。
- 节点之间允许存在空间深度差异。
- 可以显示分类名称及记忆数量，但标签应尽量简洁，不要破坏整体视觉。

八个主节点之间并非完全孤立，它们也可以通过较粗的神经连接相互关联。

### 2.2 子记忆节点

每个分类下有 N 条记忆，每条记忆都是一个独立的 **子神经节点（Memory Neuron）**。

例如：

```
决策（主神经节点）
    ├── FlyEnv 插件架构调整
    ├── Memory 使用 JSON + Markdown
    ├── 插件数据集中存储
    └── 其他决策记忆
```

子记忆节点不需要全部显示文字。

默认以大小不同的光点、能量粒子或微型发光球体呈现。

节点大小可以根据记忆的重要性、关联数量等可用数据调整，但不能凭空假设存在尚未实现的重要性评分。

只有鼠标悬停或选中节点时，才展示记忆标题、摘要等信息。

### 2.3 神经连接

这是本次设计最重要的部分。

整个可视化需要让用户明确感受到：**记忆不是孤立存在的，而是相互关联、相互影响的知识网络。**

需要具备三种层级的连接：

**第一层：分类内部连接**

每条记忆与所属分类主节点建立连接，部分相关记忆之间也可以建立连接。

形成局部神经网络。

**第二层：跨分类连接**

不同分类中的相关记忆可以相互连接。

例如：

```
事件：Windows Helper 安装失败
            │
            ▼
观察：安装流程存在权限兼容问题
            │
            ▼
决策：调整 Helper 安装流程
            │
            ▼
流程经验：先检查权限并验证安装结果
```

这些记忆虽然属于不同分类，但具有明确的关联。

连接应跨越不同的局部神经网络，形成更复杂的空间结构。

**第三层：整体网络结构**

所有主节点、子节点和连接线共同构成一个大型的三维聚合体。

远距离观察时，应该呈现类似全息球状、神经云团或复杂智能网络的轮廓。

近距离观察时，又能看到局部神经连接和单条记忆。

不要通过绘制一个固定的实体球壳来形成整体外形，而应让节点分布和连接网络自然呈现出近似球状的结构。

如果当前记忆模型没有显式的关联数据，不要伪造真实业务关系。可以使用视觉布局辅助线形成整体结构，但必须区分真实关系线与装饰性结构线。

## 三、视觉风格

参考方向：

**J.A.R.V.I.S. Holographic Interface + Neural Network + Sci-Fi Data Visualization**

### 3.1 整体效果

- 深黑蓝背景。
- 琥珀金色的精细电路和数据轨迹。
- 八种记忆类型形成不同颜色的局部神经簇。
- 大量细小发光粒子。
- 密集但有层次的神经连接线。
- 具有真实的三维空间深度。
- 部分连接线像光纤一样传输数据。
- 整体呈现悬浮的全息投影效果。

不要使用过多大面积霓虹色块。

更希望呈现的是精密、复杂、优雅的高科技仪器，而不是炫目的游戏特效。

### 3.2 空间结构

建议采用 3D Force-Directed Graph、球形聚合布局或类似方案。

主要目标：

- 八个主神经节点在三维空间自然分布。
- 每个主节点周围形成自己的记忆簇。
- 不同簇之间通过连接线交织。
- 整体大致形成球形或椭球形的记忆体。
- 中心区域也有连接和粒子，不要留下一个完全空洞的空间。
- 整体网络可以缓慢旋转。
- 用户可以自由旋转和缩放，查看不同层次。

球形是整个网络自然形成的结果，而不是一开始就绘制的固定球体。

### 3.3 动画效果

需要适度添加动态效果：

- 整体记忆体缓慢旋转。
- 主神经节点轻微脉冲。
- 子节点有非常轻微的漂浮。
- 少量粒子沿连接线流动。
- 选中节点时，相关连接线逐渐点亮。
- 其他无关节点降低透明度。
- 摄像机平滑移动到目标节点。

动画要优雅、克制，不能影响用户观察和选择记忆。

需要支持关闭自动旋转和减少动态效果。

## 四、交互设计

这不是一个纯展示动画，需要与真实记忆数据关联。

### 4.1 默认状态

显示完整的 3D 记忆体。

八个主神经节点及其子记忆网络共同形成整体结构。

默认尽量减少文字标签，突出三维结构。

### 4.2 鼠标悬停

鼠标移动到节点时：

- 高亮当前节点。
- 显示名称及类型。
- 显示关联数量等已有数据。
- 高亮直接关联的连接线。

### 4.3 点击主节点

点击“决策”等主节点时：

- 摄像机平滑聚焦到该分类。
- 高亮该分类内的记忆。
- 其他分类降低亮度。
- 可查看当前分类的记忆数量和列表。
- 可以返回全局视图。

### 4.4 点击子记忆节点

点击具体记忆时：

- 高亮该记忆。
- 高亮真实关联的节点和连接线。
- 显示记忆详情，包括标题、摘要、类型、标签和来源。
- 提供查看完整内容的入口。
- 可直接复用现有记忆详情组件。

不要在 3D 场景中直接展示长篇 Markdown。

### 4.5 搜索与筛选

需要与已有搜索和分类筛选功能关联。

搜索命中时：

- 高亮匹配节点。
- 降低不匹配节点的透明度。
- 可定位到匹配节点。
- 支持恢复完整视图。

按分类筛选时，可以突出指定类型，其余类型淡化或隐藏。

### 4.6 摄像机操作

至少支持：

- 鼠标拖动旋转。
- 滚轮缩放。
- 双击聚焦节点。
- 重置视角。
- 开启/关闭自动旋转。
- 返回完整记忆体视图。

## 五、数据与架构要求

这次任务主要修改记忆星图的可视化和交互部分。

**不要修改 AI Memory 的持久化格式、MCP 工具、记忆分类规则或现有业务逻辑。**

优先复用目前已经存在的：

- 记忆数据接口。
- 分类定义。
- 记忆关系数据。
- 搜索和筛选逻辑。
- 记忆详情 UI。
- 插件状态管理机制。

如果需要额外的图谱数据结构，应在前端实现数据转换层。

例如：

```
interface NeuralNode {
  id: string
  type: 'category' | 'memory'
  category: string
  label: string
  color: string
  size: number
  position: [number, number, number]
}

interface NeuralEdge {
  source: string
  target: string
  kind: 'membership' | 'semantic' | 'visual'
  strength: number
}
```

可以调研 Three.js、3d-force-graph 等适合当前项目技术栈的可视化方案。

优先考虑稳定性、性能和与现有 FlyEnv 插件架构的兼容性。

不必为了实现视觉效果引入复杂的额外后端服务。

## 六、性能要求

记忆数量可能持续增长，因此不能只针对几十个节点设计。

需要考虑：

- 不同数量级的节点渲染性能。
- 避免每个节点都创建复杂 DOM。
- 合理使用 InstancedMesh、BufferGeometry 等 GPU 渲染技术。
- 对大量连接线进行分级显示。
- 默认隐藏低优先级文字标签。
- 根据镜头距离调整视觉细节。
- 避免一直运行高成本的布局计算。
- 页面隐藏或切换后暂停渲染。
- 组件卸载后正确释放 WebGL 资源。

优先保证几百条记忆时能够平滑操作，再根据真实数据优化更大规模的情况。

## 七、最终验收效果

希望最终得到这样的视觉体验：

**远看：** 一个由无数发光神经节点和复杂连接网络聚合而成的巨大 3D 智能记忆体。

**中距离：** 可以识别八个不同颜色的主神经节点，它们分别控制不同类型的局部记忆网络，彼此通过大量神经连接相连。

**近看：** 能够观察每条记忆、节点间的关系，以及不同分类之间的知识关联。

**交互时：** 记忆体会对用户操作产生反馈，相关神经网络被点亮、聚焦和展开，呈现一种正在探索 AI 长期记忆的感觉。

最终目标不是一个炫酷的静态动画，而是一个真正可以操作、探索和管理的 **3D Neural Memory Visualization**。

请先检查 FlyEnv 当前记忆星图相关代码、数据结构和已使用的可视化库，在现有架构上完成改造。优先复用现有能力，不要重新实现整套记忆管理系统。

视觉稿可以作为风格参考，但以本需求描述、真实数据结构和现有项目兼容性为准。

## 我再补充两个设计建议

第一，八个主神经节点不一定要永远固定在最外层。

你提供的参考图最吸引人的地方，是整个结构由大量精细节点自然组成，而不是八颗大球围成一个圈。因此主神经节点应该分布在不同深度，有些靠近中心、有些靠近表面，让网络具有真正的三维层次。

第二，连接线的视觉密度可以远高于真实业务关系数量，但要区分两者。

例如只有 100 条记忆、20 条真实关联，也能通过细小的装饰性粒子和局部神经纤维形成复杂的全息外观。不过，用户点击查看的关系必须是真实的，不能把装饰线当成已建立的知识关联。

我建议本地 AI 先完成纯 3D 星图组件及模拟数据预览，再接入真实记忆数据和现有交互。这样可以更快判断视觉方向是否达到你想要的效果，也避免在改动业务逻辑之后才发现整体视觉不合适。
