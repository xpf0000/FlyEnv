# hosts 空行累积修复

## 原因与实施范围

Unix Helper 的 `mergeManagedHosts` 追加区块时写入末尾换行，退出清理仅删除
BEGIN/END 标记及其中内容，遗留该换行；下次追加再写一个，形成累积。

删除区块时，如果前面已在行首，同时删除其后紧邻的一组 LF 或 CRLF；如果前面
还有同行文字，则保留换行，避免将用户内容或保留的区块与后文拼接。
保留区块前的内容、原有空行和尾部其他内容；替换保留的区块不改行尾。
已有历史空行不批量压缩。没有末尾换行的区块不删除相邻字符；原 hosts 最后一行
未换行时，首次追加需要补齐行分隔，后续启动/退出保持稳定。
修复限定在 macOS/Linux 共用的合并函数，Windows 写入流程不变。

## 操作契约与失败边界

- 既有 Host 模块/退出流程发起同步，UnixHosts 队列持有请求直至终态；Helper
  `hostsStore` 持有文件读写锁、快照摘要校验和原子发布。本次不新增状态或 IPC。
- 无中间事件；终态仍为 changed 布尔值或错误，重复同步无变化，重复清理无变化。
  与服务启停无新增依赖，退出仍先等待已接纳 hosts 操作。
- 合并、快照校验和文件写入为必要步骤，失败阻断本次写入并如实传播；模糊标记
  仍拒绝修改。DNS 刷新是写入后的附加动作，失败不覆盖完成结果或重放写入。
- 新模块约束核对：无新模块、持久化、Pinia、共享领域属性或服务启停流程；无需例外。
- Helper 发布版本同步为 v48，重建各平台产物，Linux 构建触发号升为 91。
