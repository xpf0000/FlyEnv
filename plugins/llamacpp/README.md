# llama.cpp plugin 0.2.0

每个 GGUF 主模型独立保存启动配置；服务监听地址、端口和 API key 文件是公共设置。保留原来的服务、运行时、模型、设置、日志五个入口，设置内分为“服务设置”和“模型设置”。

## 关联多模态投影

1. 在模型库下载主模型及对应的 mmproj 文件，或准备已有本地投影文件。
2. 打开主模型的“配置”，选择“使用投影文件”。列表按同仓库/已记录提交推荐候选，必须由用户确认；下载本身不会自动关联。
3. 选择已下载的投影，或用“选择本地文件”引用外部文件。外部文件不复制、不导入下载目录，也不由插件删除。
4. 选择检查用的运行时，检查兼容性、查看命令及独立 argv 列表。保存只写配置；服务模型可以“保存并启动/重启”。编辑其他模型不会切换当前服务模型，切换使用单独的“设为服务模型”。
5. 在“本次运行”查看实际启动快照、已传入的投影和运行时报告的输入能力。传入投影不等同于已验证图片、音频或视频请求成功。

GGUF 检查读取有界元数据和张量目录，不加载模型权重；识别主模型、投影、分片和 draft/MTP 辅助文件。新下载文件保存检查描述，元数据识别的投影不依赖 `mmproj` 文件名。旧记录缺少描述时，文件名仅提供未验证候选。分片不作为单文件主模型启动。

引用按仓库、revision、相对路径标识；保存大小和已有 SHA-256，外部引用还保存 mtime。启动前检查可读性、路径边界、当前 sidecar 身份和指纹变化。主文件指纹变化时，需要明确确认沿用配置；已关联的辅助文件变化需要重新选择。相同文件可以被多个模型引用，删除前列出引用者；本次运行依赖由 Fork 再次保护。缺少 SHA/提交证据显示未验证，不推断相同 `main` 一定兼容。

## 高级参数

| 分组 | 设置 |
| --- | --- |
| 基础资源 | 上下文、生成/批处理线程、GPU 层数和设备、batch/ubatch、并发槽、API 模型别名 |
| 性能与内存 | Flash Attention、K/V cache 类型、KV 卸载、加载方式、连续批处理、context shift、多 GPU split/tensor ratio/main GPU |
| 多模态 | 投影 GPU 卸载和设备、每图最少/最多 token、编码批次 token |
| 模板与思考 | 模型内置/命名/本地模板、Jinja、JSON kwargs、思考开关/预算/强度/输出格式 |
| 投机解码 | 运行时默认、禁用、普通 draft、内置 MTP、ngram；draft 文件、线程、token 上下限及后端设备 |
| 采样默认值 | temperature、top-p/k、min-p、重复/存在/频率惩罚、seed、默认输出 token |
| 额外参数 | 引号路径、JSON、正反开关、短别名、重复参数及多值参数；统一来源冲突检查 |

新高级项默认跟随运行时，未设置便不传参；合法的 `0`、`false`、`-1` 保留。每个 CPU/CUDA/Vulkan/Metal 后端独立保存 GPU 配置；CPU 启动使用零层并休眠 GPU 项，不清空其他后端保存值。没有启用投影时，投影专属细项休眠。

实际支持根据所选二进制 `--help` 探测，设备来自 `--list-devices`。缓存按二进制真实路径、版本、后端、大小、mtime 区分；设备短时缓存。缺少参数的旧版本保留保存值，应用时报告不支持。检查目标不会自动更换服务运行时。不推断驱动、显存是否足够或所有参数组合一定可加载。

额外参数只接受参数，不包含可执行文件，不展开变量/通配符/命令替换，不执行 shell。表单和额外参数不能重复设置同一项，受 FlyEnv 管理的模型来源、服务监听、认证、日志及路由参数禁止覆盖。额外参数中的投影显示来源，并可显式移入表单；文本模式与投影冲突会阻止启动。复制命令包含 cwd；Windows 为 PowerShell，Unix 为 POSIX，显示文本不会回流到进程执行器。

继承的非密钥 `LLAMA_ARG_*` / `MTMD_*` 在预览中单独显示，并使用现有 EnvSync。无法明确归属的模型下载/路由来源及隐式辅助文件依赖要求先清除环境配置；argv 预览不能涵盖所有未知环境影响。API key 只显示文件路径。客户端请求可以覆盖采样默认值，工具调用仍取决于模型、模板及客户端请求，没有另设 Cline 开关。

## 保存、应用与恢复

配置通过 `StorageGetAsync` / `StorageSetAsync` 存于 `flyenv-llama-cpp-settings-v2`，下载目录保留原键；首次迁移保留旧配置。没有新增 Pinia、共享 `config.setup` 或宿主代码。草稿属于组件，离页可保存、放弃或继续编辑；恢复默认只修改当前草稿。

controller 拥有预览、能力检查、应用、下载及删除操作，串行提交不会覆盖其他模型的配置。应用使用进入操作时的不可变快照，先预检、再保存、再走既有通用 start/restart；预检失败不停止旧服务。保存完成而重启失败显示部分完成，保存结果保留，不宣称已经应用。停止失败不继续启动。

Fork 拥有 PID、当前运行依赖及上次成功快照，只在健康检查成功后登记。工作进程重建且已有服务时显示运行配置未确认；未知状态不猜测参数。确认外部进程退出后清除活动依赖。停止后可核对上次成功命令，再执行恢复；恢复不覆盖正式保存配置，不无限重试。重启 FlyEnv 后重新读取持久配置，但不会把持久配置冒充既有进程快照。

下载文件完成后目录记录失败显示部分完成，点击“重试登记下载记录”只补登记，不重新下载。同路径新记录替换旧目录记录，不自动确认旧模型配置的指纹。删除已完成但记录清理失败也保留已完成事实；再次操作只补清理。

健康检查后的能力观察是附加动作：读取 `/props`，必要时回退 `/v1/models`，单请求 1500ms、总预算 5 秒。支持数组/布尔对象模态及 architecture.input_modalities；无报告、401、404、超时均显示未知/原因，不推翻成功启动，不主动开启 props 写接口。
